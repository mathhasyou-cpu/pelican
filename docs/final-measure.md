# Замеры доработок к финалу

Что и в каком порядке мерить на машине с корпусом и LM Studio, и по какому правилу
включать каждую доработку. Правила записаны ДО прогона: менять их по итогам замера —
значит подгонять тест под ответ (CLAUDE.md, «пороги подбираются замером»).

Источник требований — консультация с экспертами заказчика 16.10: ТОП слишком зрелый
(«90% — достаточно зрелые технологии»), мерило — «увидеть "Attention is all you need" в
2018 году»; отделить зарождающееся от слабого сигнала («маленький тренд, патентный
подтверждённый»); смотреть шире IT; сравнить локальную модель с облачной; расширить
источники.

## Что включено всегда, а что — флагом

Всегда (починки, порядок ТОП не меняют):
- «Почему это слабый сигнал» пишет карточка, с дословной цитатой-опорой
  (`card.verified_quote`, приём ALCE) — на стенде это поле пустело у 5–8 карточек из 12–15;
- блок «Патенты» в теле карточки (раньше — в свёрнутом разделе, эксперт его не увидел);
- новостной поиск по кандидату: повтор отказавших запросов и пометка «новости не
  проверены» (`live.news_many_measured`);
- серверы препринтов (bioRxiv, medRxiv, Research Square…) — тип «препринт» (`weak.trust`).

Флагом (`weak/flags.py`), по умолчанию выключено:

| флаг | что делает |
|---|---|
| `WEAK_ONPOINT_COMPANIES=1` | компания идёт в «Кто делает», только если её заголовок про эту технологию |
| `WEAK_LAYERS=1` | три слоя: уже тренд → исключено; слабый сигнал → ТОП; зарождающееся → «наблюдать» |
| `WEAK_TECHNIQUE=1` | приём за направлением; нет приёма сверх категории → «слишком общая категория» |
| `WEAK_EXTRA_SOURCES=1` | гранты NIH, препринты Europe PMC, ClinicalTrials.gov, каталог YC |

## Порядок

### 0. Тесты

```bash
pip install -e ".[dev,ml]"
pytest
```

### 1–2. Ретро-тест: база и каждый флаг — плечами одного прогона

```bash
python scripts/retro_hits.py --arms base,layers,technique,onpoint,extra-layers
python scripts/measure_arms_tz.py      # те же плечи на запросах ТЗ, на сегодня
```

Плечо `base` — без флагов, `extra-layers` — `WEAK_EXTRA_SOURCES` вместе с `WEAK_LAYERS`.
⚠️ Плечи идут подряд на каждом срезе с включённым кэшем живого поиска, а не прогонами
по очереди: прогон всех срезов — часы, кэш живёт сутки, и последовательные прогоны
сравнивали бы флаг с другим набором новостей. Таблицы —
`reports/retro/<плечо>/retro-hits.md` и `reports/arms-tz/arms-tz.md`; оборванный прогон
продолжается тем же вызовом (готовые JSON пропускаются).

Читать вместе с колонкой «работ в корпусе на
дату»: arXiv в корпусе — cs, eess, stat.ML, cond-mat.mtrl-sci, q-bio; OpenAlex —
материалы, энергетика, химия, CS, инженерия, причём CS и Engineering только с 2023-01.
Биомедицины в OpenAlex нет, так что строки биотеха (CRISPR, органоиды, мРНК) — проверка
прежде всего денежного потока и новых источников, а не корпуса.

**Правило включения флага** (любой из них):
1. ретро-тест: «в ТОП или наблюдать» — не меньше базы, и «в ТОП-15» — не меньше базы.
   Для четырёх флагов не замерено: до починки `tech.run_tech` научный поток под срезом
   не называл ни одной работы (`docs/todo.md` §115);
2. датасет заказчика: `measure_signal_kinds.py` флагов не читает — оценка зрелости идёт
   до них, recall 0.90 и specificity 1.00 от флага не меняются по построению;
3. живые примеры ТЗ (`measure_arms_tz.py`): меньше карточек-категорий и Big
   Tech-направлений с продажами в ТОП, чем в базе. Категория — ярлык, целиком равный
   термину из `CATEGORIES` в скрипте («DeFi», «RAG», «Zero Trust», «Agentic AI»…); список
   записан до прогона плеч и по итогам не правится. Big Tech с продажами — правило слоя
   «уже тренд» из `weak.layers` (крупный игрок и продажи или раунд).

Плюс у каждого своё:
- `WEAK_ONPOINT_COMPANIES` — на отчёте «технологии в ИИ» нет ASUS, UGREEN, D-Link и других
  компаний из заметок не про технологию; число игроков у верных направлений не упало вдвое;
- `WEAK_LAYERS` — трансформеры на срезе 2017-12-01 не в «уже тренд»; в «наблюдать»
  попадают одиночные работы без компаний и патентов;
- `WEAK_TECHNIQUE` — снимает не больше трети ТОП (больше — режет не категории, а всё);
- `WEAK_EXTRA_SOURCES` — хотя бы у трети строк биотеха и энергетики ретро-теста появляется
  грант, препринт или испытание; на ИИ-строках ничего не ломается.

Не прошёл — флаг остаётся выключенным, а в `docs/todo.md` пишется, что именно провалилось.

### 2б. Слои после починки (плечи `base2`, `layers2`, `extra-layers2`)

```bash
python scripts/measure_arms_tz.py --arms base2,layers2,extra-layers2
python scripts/retro_hits.py --domain <домен> --arms base2,extra-layers2   # кроме ИИ
```

**Правило включения** (все три, на запросах ТЗ): ТОП — 15 позиций на всех четырёх;
Big Tech с продажами в ТОП меньше, чем у `base2`; «hardware acceleration for fully
homomorphic encryption» и «quantum-driven model optimization», если они в пуле, — не в
«уже тренд». Для `extra-layers2` плюс своё правило из шага 2 — по строкам биотеха и
энергетики ретро-теста.

### 2в. Нулевой контроль и добор до 15 (плечи `base2`, `extra-layers3`)

```bash
python scripts/measure_arms_tz.py --arms base2,extra-layers3 --reps 3
```

Три повтора каждого плеча на одном кэше новостей — разброс самой системы.
**Правило** (для `extra-layers3`, все три): ТОП 15 на всех четырёх запросах во всех
повторах; Big Tech с продажами (сумма по четырём запросам) — наибольшее по повторам
`extra-layers3` меньше наименьшего по повторам `base2`; медиана времени не больше
`base2` плюс 120 с. ⚠️ Правило 1 ретро-теста вне ИИ провалено одним прогоном (2 против 3,
§116); нулевой контроль покажет, различимы ли такие разности вообще, но правило задним
числом не переписывается.

### 2г. Финал к сдаче (плечи `base4`, `final` — поверх исправлений ревью)

```bash
python scripts/measure_arms_tz.py --arms base4,final --reps 2
python scripts/retro_hits.py --arms final            # все домены; базы — base, base2
python scripts/judge_precision.py ...                # ТОП `final`: gemma и gigachat
```

`final` = `WEAK_EXTRA_SOURCES=1 WEAK_LAYERS=1` (слои с починкой и добором до 15).
**Правило включения на стенд — «не хуже базы»** (решение владельца под срок, §117): ТОП 15
на всех четырёх запросах в обоих повторах; Big Tech с продажами в ТОП не больше
наибольшего у `base4`; медиана времени не больше `base4`. Всплеск (`WEAK_BURST`) и
1F50D в финал не идут (§114, `docs/corpus-1f608.md`).

### 2д. Срок раннего обнаружения (конфигурация стенда)

```bash
python scripts/retro_hits.py --hits scripts/retro_lead.tsv --arms final
```

Семь технологий ИИ, у каждой — срезы через **6, 12 и 18 месяцев после ключевой статьи**
(`scripts/retro_lead.tsv`), запрос «технологии в ИИ», плечо `final`. Приём — оценка на
«дебютных» темах с временем обнаружения (Augur, Salatino и др.): метрика — **первый срез,
на котором технология вошла в ТОП-15**, то есть «через N месяцев после статьи, за M до
бума». Порядок прогона — все +12, потом +18, потом +6: оборванный прогон оставляет самые
информативные срезы. ⚠️ Срезы `retro_hits.tsv` (декабри) стояли через 2–6 месяцев после
статьи у ViT, BERT, трансформеров и диффузионных моделей — раньше, чем объявленные
«год-полтора»; этот набор их заменяет. Даты и псевдонимы записаны до прогона.

### 2а. Направления из всплеска (`WEAK_BURST`, плечи `burst` и `burst-only`)

```bash
python scripts/measure_retro_reach.py                       # досягаемость, без модели
python scripts/retro_hits.py --domain ИИ --arms base,burst,burst-only
python scripts/measure_arms_tz.py --arms base,burst,burst-only
```

**Правило включения** (все три):
1. ретро-тест на строках ИИ: до пула кандидатов доходят не меньше двух строк из 14 хотя бы
   в одном плече всплеска (база — 0); `burst-only` — честное плечо, направления модели
   на срезе знают будущее;
2. запросы ТЗ: ТОП — 15 позиций на всех четырёх; Big Tech с продажами в ТОП меньше базы;
3. время запроса — медиана не больше базы плюс 120 с.

### 3. Локальная модель против облачной (sonar)

Генерация — sonar, эмбеддинги — по-прежнему LM Studio (корпус записан его векторами):

```bash
LLM_BASE_URL=https://api.perplexity.ai LLM_MODEL=sonar LLM_API_KEY=$PERPLEXITY_API_KEY \
LLM_REASONING_EFFORT= EMBEDDING_BASE_URL=http://localhost:1234/v1 EMBEDDING_API_KEY=lm-studio \
python scripts/measure_signal_kinds.py --evidence mixed
```

Пишет `reports/weak-assess-mixed-sonar.tsv` рядом с локальным `weak-assess-mixed.tsv`
(файл с меткой модели — локальный замер не перезаписывается). Цена — около $0.005 за вызов,
на 130 строк ≈ $0.7 за плечо. Свести в таблицу «локальная / sonar»: F1, recall, precision,
стадия точно, время, цена, где живут данные — в `reports/weak-eval.md` и техдоку.

⚠️ sonar сам ищет в интернете. Сравнение — «локальная модель на наших свидетельствах»
против «sonar на наших свидетельствах плюс его собственный поиск»: для облака это
верхняя граница, так и подписывать. Уже измерено (для слайда): независимый судья GigaChat
признаёт сигналом 84% карточек ТОП против 96% у своей модели; в copycat sonar нашёл 0 из
34 реальных российских аналогов, а локальная модель с поиском Яндекса — 24 из 34.

### 4. Стенд

Включить прошедшие флаги в `.env` стенда, `docker compose up -d --build`, прогнать три
примера ТЗ и два запроса вне финтеха («биотехнологии», «перспективная энергетика») и
посмотреть карточки глазами: приём, подтверждение, объяснение, блок «Патенты».
