## 2. Краткое описание

ML-инженер прогоняет конвейер на состоянии мира прошлой даты (point-in-time: корпус обрезан
датой, новости — окном, всё из будущего отброшено) и сверяет верх выдачи с тем, что случилось
потом: приростом следа ядра в корпусе за горизонт и новостями после среза. Результат — ответ
на вопрос жюри о предсказательной силе и срезы `reports/bt-<дата>/`, которые служат входом
обучения модели роста (UC-24). Отдельный ретро-тест проверяет, видит ли система будущие
прорывы на дату, когда они были одной-двумя работами.

## 3. Предусловия

- Корпус и шарды наполнены; у работ есть `observed_at` (дата публикации); известен состав
  срезов OpenAlex по дате края (`weak.core.SLICES`; CS и Engineering — только с 2023-01).
- Сервер моделей запущен; замок модели свободен.
- Датасет методолога на месте (для покрытия судьёй); для ретро-теста — `scripts/retro_hits.tsv`
  (26 технологий: tech, aliases, cut, query, domain, why).
- Кэш живого поиска: для плеч одного среза — включён и одинаков для всех плеч.

## 4. Триггер

Подготовка защиты (число «строк списка 2026 находит прогон на 2024»), изменение конвейера,
обучение модели роста (UC-24 требует свежих срезов), проверка доработки за флагом (UC-26).

## 5. Основной поток

1. ML-инженер запускает прогон под срезом по шести доменам датасета — тем же `measure_ask.py`,
   без второго конвейера:
   ```bash
   python scripts/measure_ask.py --domains --cached --as-of 2024-09-15 --out reports/bt-2024-09-15
   ```
2. Система для каждого домена выполняет `ask.run` с `weak.asof`: корпус — работы до среза,
   новости — окно `after:`/`before:`, источники без даты (Хабр, КиберЛенинка) — лишнее
   отбрасывается после выдачи; пишет `ask-cards-<домен>.json` (ТОП, снятые по жанру, с одним
   игроком).
3. ML-инженер считает исход:
   ```bash
   python scripts/backtest_signals.py --dir reports/bt-2024-09-15
   ```
4. Система для каждого ядра пула считает след на срезе и на горизонте `HORIZON_YEARS = 2`
   одним набором срезов корпуса на текущем корпусе (не из карточки), новости после среза явным
   окном; «выросло» = прирост ≥ `GROWTH = 2.0`; строки с базой ниже `MIN_BASE = 5` — отдельной
   категорией; пишет `backtest.tsv`, AUC Манна–Уитни «верх против контроля того же пула» и пол
   случайности перестановкой.
5. ML-инженер проверяет правило, записанное до прогона (докстринг `backtest_signals.py`):
   предсказательная сила показана, если верх выдачи растёт чаще контроля — по медиане
   прироста работ И по доле направлений с новостями после среза. Мерила «заметно» в коде
   нет: скрипт печатает по ТОП и контролю медиану прироста, долю выросших ≥ `GROWTH = 2.0`
   и долю с новостями после среза (с интервалом `stats.span`), а также AUC Манна–Уитни
   «ТОП против контроля» по строкам с базой ≥ `MIN_BASE` рядом с полом случайности
   (медиана и 95-й перцентиль перестановок); вердикт по этим числам выносит ML-инженер.
   Совпадение медиан — «не показано».
6. ML-инженер считает главное число защиты — покрытие списка методолога 2026 прогоном на
   срезе (судья видит только названия):
   ```bash
   python scripts/judge_match.py --dir reports/bt-2024-09-15
   ```
7. ML-инженер прогоняет модель этапа 1 на тех же кандидатах среза:
   ```bash
   python scripts/backtest_classifier.py --dir reports/bt-2024-09-15 [--no-judge] [--no-money] [--embed] [--reassess]
   ```
   `--no-money` — без денежного следа (Google News, ~4000 запросов на срез): столбцы `$` и
   денежные исходы пустые, модели роста (`--in-query`, `grew_excess`) они не нужны; так
   посчитаны срезы в git. `--embed` — соседство в векторах под срезом (`E`, проход по шардам).
   `--reassess` — переоценить моделью, даже если чтения `J` уже есть в прошлом TSV.
   Система оценивает свидетельства среза (`weak.assess` → чтения `J`), считает числа `N`,
   вероятность `weak.model.probability`; сравнивает три оценщика (классификатор, gemma на срезе,
   членство в ТОП) по AUC против пола; пишет `backtest-classifier.tsv` — вход UC-24.
   Правило до прогона: сила показана, если AUC классификатора выше пола И не ниже AUC ТОП;
   иначе «модель выучила датасет, а не будущее» (базовая линия: AUC 0.48 и 0.38 при поле 0.57
   — так и предъявлено, модель этапа 1 в выдаче не считается).
8. ML-инженер повторяет шаги 1–7 для срезов 2020-09-15 и 2022-09-15 (один горизонт и один
   набор срезов у всех), фиксирует результаты в техдоке §10 и `reports/`.

## 6. Альтернативные потоки и потоки исключений

**A1. Ретро-тест «увидеть Attention в 2018»** (шаг 1). Оценка на дебютных темах: для каждой
строки `scripts/retro_hits.tsv` — прогон на её дату среза и поиск технологии в выдаче по
псевдонимам целым словом:
```bash
python scripts/retro_hits.py [--domain ИИ] [--cached] [--arms base,layers,...] [--report-only]
```
Выход — `reports/retro/<срез>-<запрос>.json` и `reports/retro/retro-hits.md` (технология /
срез / где оказалась: top с номером, watch, beyond, excluded с жанром, missing / след в
корпусе на дату / пол случайного порядка 15 / N). «Не найдено» при нуле работ в корпусе — потолок
источников, не промах ранжирования. Честное плечо — `WEAK_BURST=only` (направления модели
знают будущее). Базовая линия на 14 строках ИИ: 1 в ТОП-15 при направлениях модели, 3 с
всплеском, 2 при одном всплеске; вне ИИ — 3 без флагов (техдока §10).

Срок раннего обнаружения (`docs/final-measure.md` §2д, конфигурация стенда) — тот же скрипт
на другом наборе срезов:
```bash
python scripts/retro_hits.py --hits scripts/retro_lead.tsv --arms final
```
`--hits` (по умолчанию `scripts/retro_hits.tsv`) задаёт набор; `scripts/retro_lead.tsv` — семь
технологий ИИ, у каждой срезы через 6, 12 и 18 месяцев после ключевой статьи (21 строка),
запрос «технологии в ИИ»; метрика — первый срез, на котором технология вошла в ТОП-15. Даты и
псевдонимы записаны до прогона. Результат не перемерен (в `final-measure.md` §2д чисел нет).

**A2. Лесенка горизонтов** (шаг 4). С какого срока после среза исход виден:
```bash
python scripts/backtest_horizons.py --dir reports/bt-2020-09-15,reports/bt-2022-09-15,reports/bt-2024-09-15
```
Работы с датой 1 января (заглушка OpenAlex) выброшены на всех горизонтах; выход —
`reports/backtest-horizons.md/.json`.

**A3. Метка списка заказчика** (шаг 7) — `label_listed.py --dir reports/bt-<срез>` (UC-23 A4)
дописывает `listed` в `backtest-classifier.tsv`.

**A4. Пересчёт таблиц без прогона** (шаги 1, A1) — `--report-only` по готовым JSON; оборванный
прогон продолжается тем же вызовом (готовые JSON пропускаются), `--fresh` перезапускает.

**E1. Срез беднее настоящего прошлого** (шаг 2). На 2024-09-15 из 3.86 млн работ в поиске
остаются ≈ 0.4 млн; бэктест проверяет прежде всего денежный поток. Это нижняя оценка, так и
предъявляется.

**E2. Корпус докачан после прогона среза** (шаг 4). След «на срезе» из карточки не годится —
оба конца считаются заново на текущем корпусе одним набором срезов; иначе докачка читалась бы
как рост.

**E3. Отказ сервера моделей или замок занят.** Отказ модели — как в UC-23 E1. Замок модели
держат `measure_ask.py` (шаг 1), `retro_hits.py` (A1), `backtest_classifier.py`,
`judge_match.py`, `label_listed.py` (`locks.Busy` → код 75, UC-23 E2, `NFR-26`);
`backtest_signals.py` модель не вызывает и замка не берёт.

## 7. Постусловия

- Успех: папки `reports/bt-<срез>/` с `ask-cards-*.json`, `backtest.tsv`, `backtest-classifier.tsv`,
  `judge-coverage.tsv`; таблицы `reports/retro/retro-hits.md`; вердикт по правилу записан
  (показано / не показано) в техдоке §10. Базовая линия (срезы 2020 / 2022 / 2024): AUC «ТОП
  против контроля» по строкам с базой ≥ `MIN_BASE` — 0.63 / 0.60 / 0.60 при поле 0.57
  (`reports/bt-*/backtest.json`), то есть ТОП делит рост слабо, на 0.03–0.06 выше пола;
  покрытие списка методолога сентября 2026 — 16 / 16 / 23 строки из 100 (`docs/weak-audit.md`
  в корне репозитория, `042fde6`).
- Отказ: прогон прерван — готовые JSON остаются, повтор доделывает; таблицы не пишутся
  частично.

## 8. Особые требования

- BR-49, BR-50 (правило зачёта до прогона; совпадение медиан — «не показано», не повод
  крутить пороги), BR-52.
- NFR-26 (замок модели), NFR-39, NFR-44.
- Один горизонт и один набор срезов корпуса у всех срезов (rolling-origin): иначе модели
  несравнимы.
- Верх сравнивается только с контролем того же пула; верх-k из разных прогонов несравнимы.
- Перед каждым прогоном: папка выхода `reports/bt-<дата>` не содержит прогонов другого правила
  (новые плечи — свои папки, как `base2`); замок модели и окно GPU согласованы — прогон шести
  доменов идёт часы; кэш живого поиска для плеч одного среза общий.
- Ограничение «дата публикации vs дата доступности»: `works.collected_at` есть с октября 2026,
  бэктест по доступности пока невозможен (техдока §11).
