## 2. Краткое описание

После каждой докачки (UC-20) или перелива (UC-22) ML-инженер доказывает, что корпус
собран: помесячная сверка числа работ в `works` с `meta.count` того же запроса к OpenAlex
по каждому срезу и погодовая сверка arXiv с `totalResults`. Диапазон min/max полноту не
доказывает (корпус полгода выглядел собранным при девятнадцати отсутствующих месяцах);
только этот скрипт считается доказательством. Скрипт печатает команды докачки под
найденные дыры. Отдельная разовая уборка — повторные версии препринтов arXiv.

## 3. Предусловия

- Корпус в `works` наполнен (UC-20 / UC-22); Postgres доступен (`settings.storage_target`).
- Сеть до `api.openalex.org` и `export.arxiv.org`; для OpenAlex задан
  `OPENALEX_API_KEY` с остатком бюджета хотя бы на число месяцев × срезов (по умолчанию
  5 лет × 6 срезов = 360 запросов плюс по одному на имя поля).
- `OPENALEX_FILTERS` и `ARXIV_CATEGORIES` те же, что при сборе (сверяется «тот же
  запрос»).

## 4. Триггер

Завершён прогон сбора или перелива; или выдача подозрительно бедна научными работами за
какой-то период.

## 5. Основной поток

1. ML-инженер запускает сверку:

   ```bash
   python scripts/verify_science_corpus.py                      # все срезы из настроек плюс arxiv
   ```

2. Для каждого среза OpenAlex (`settings.openalex_filters`) система спрашивает у источника
   человеческое имя поля (`field_name`), читает из `works` число работ по месяцам
   (`db_months`) и самый старый день (`db_edge`), строит месяцы за `--years` (5) назад.
3. Для каждого месяца система запрашивает `meta.count` того же фильтра
   (`from_publication_date … to_publication_date … scope`, `per_page=1`) с паузой
   `openalex.DELAY_S` = 0,2 с и сравнивает с базой: недобор больше `HOLE_RATIO` = 1 % —
   «ДЫРА»; последние `TAIL_MONTHS` = 2 месяца — «свежий край, индекс догоняет» (не дыра);
   месяцы старше края корпуса — «старый край корпуса».
4. Система печатает по срезу строки с пометками, итог «api / бд / не хватает» и «дыр нет»
   или «дырявых месяцев: k».
5. Для arXiv система читает счёт по годам из базы и для каждого года запрашивает
   `totalResults` того же запроса (`query_head AND submittedDate:[год]`), выдерживая
   `arxiv.DELAY_S` = 3 с до запроса (`arxiv_total`, до `ARXIV_TRIES` = 3 попыток с растущей
   паузой); расхождение > 1 % — «ДЫРА», год старого края — «старый край корпуса».
6. Если дыры найдены, система печатает команды докачки (`refill_commands`): смежные дыры
   склеиваются в диапазоны, каждый режется на куски по `CHUNK_DAYS` = 300 суток, смещения
   `--skip-days`/`--days` считаются от сегодня:

   ```
   === чем закрыть (по одному процессу за раз, PowerShell) ===
     $env:OPENALEX_FILTERS='<срез>'; python -m pelican.collect -s openalex --skip-days S --days D
     # после докачки: $env:OPENALEX_FILTERS=$null и этот скрипт заново
   ```

7. ML-инженер выполняет команды (UC-20 A1, A3) и запускает сверку заново, пока «дыр нет».

## 6. Альтернативные потоки и потоки исключений

**A1. Один источник или глубина (шаг 1).**

```bash
python scripts/verify_science_corpus.py --source openalex --years 5
python scripts/verify_science_corpus.py --source arxiv
python scripts/verify_science_corpus.py --slice primary_topic.field.id:fields/25
```

**A2. Уборка повторных версий arXiv.** До появления `Store._new_arxiv_versions_only`
суточный сбор писал v1 и v2 одной работы двумя строками с одной датой (двойной счёт в
следе самых свежих работ):

```bash
python scripts/dedupe_arxiv_versions.py            # показать: «повторных версий: N» и 5 примеров
python scripts/dedupe_arxiv_versions.py --apply    # удалить, сохранив строки в data/arxiv-version-dupes-<дата>.tsv
```

Выживает младшая версия (`row_number() … ORDER BY ver, id`); у удаляемых уходят их
`tech_mentions`; векторы удалённых id в шардах остаются (поиск вернёт id, работа в базе
не найдётся и в свидетельства не попадёт). Возврат — `COPY works (...) FROM` из TSV.

**A3. Сверка числа векторов.** Полнота векторов (UC-21) проверяется `science_progress.py`:
`done` из `state.json` против `count(*)` корпуса; расхождение закрывается докачкой.

**E1. Бюджет OpenAlex исчерпан (шаг 3).** Ответ 429 (или JSON без `meta`):
`BudgetSpent` с остатком из заголовков `x-ratelimit-remaining-usd` /
`x-ratelimit-limit-usd` и временем сброса (полночь UTC); сверка OpenAlex прекращается с
«⚠️ openalex: …», сверка arXiv (бесплатная) всё равно выполняется. Повторить после сброса.

**E2. arXiv отказывает по частоте (шаг 5).** 429 «Rate exceeded» (по IP) или молчание до
таймаута: год помечается «arXiv не ответил — год не сверен» (не ноль и не дыра); после
`REFUSALS_BEFORE_STOP` = 2 отказов подряд перебор лет прекращается («не сверен — arXiv
отказывает по частоте»), чтобы не продлевать окно лимитера.

**E3. Корпус моложе окна сверки (шаг 2).** «корпус начинается <дата>, запрошено с <дата>
— старый край мельче окна»: месяцы до края не считаются дырами.

**E4. База недоступна.** Скрипт падает на открытии `Store`; ничего не записано (скрипт
только читает по построению).

## 7. Постусловия

**Успех.** По каждому срезу и году напечатан статус; «дыр нет» — корпус признан полным на
глубину `--years` с точностью `HOLE_RATIO`; в базу ничего не записано.

**Дыры найдены.** Список месяцев и готовые команды докачки; корпус не признаётся полным
до повторной сверки.

**После A2 с `--apply`.** Повторные версии удалены, резервный TSV в `DATA_DIR`.

## 8. Особые требования

- `BR-49` (`HOLE_RATIO`, `TAIL_MONTHS` — из замера расхождений 0,0–0,2 % у собранных
  месяцев; свежий край недосчитан всегда).
- `NFR-59` (повторная докачка дыр не создаёт дублей), `NFR-60` (`collected_at`),
  `NFR-69` (паузы arXiv/OpenAlex, бюджет из заголовков, `User-Agent`).
- Сверка — тем же запросом, что сбор (те же фильтры и категории); иначе сравниваются
  разные множества.
- Только чтение: ни одного метода записи `Store` (`verify_science_corpus.py`).
  `dedupe_arxiv_versions.py` пишет только с `--apply` и только после резервной копии.
- Перед каждой сверкой бюджет OpenAlex оценён (месяцы × срезы запросов).

## 9. Точки расширения и включения

- Приёмочный шаг UC-20 и UC-22; команды докачки возвращают в UC-20 A1.
- Полнота векторов — UC-21 A1 (`science_progress.py`).
- Предложено: запуск сверки по расписанию вместе со сбором (`FEAT-42`, `OQ-06`).

## 10. Данные и интерфейсы

- CLI: `python scripts/verify_science_corpus.py [--source all|arxiv|openalex] [--years N]
  [--slice <фильтр>]…`; `python scripts/dedupe_arxiv_versions.py [--apply]`.
- Константы: `HOLE_RATIO = 0.01`, `TAIL_MONTHS = 2`, `CHUNK_DAYS = 300`, `ARXIV_TRIES = 3`,
  `REFUSALS_BEFORE_STOP = 2`; `arxiv.DELAY_S = 3.0`, `openalex.DELAY_S = 0.2`;
  `--years` по умолчанию 5.
- Запросы: OpenAlex `GET /works?filter=from_publication_date:…,to_publication_date:…,<scope>&per_page=1`
  (`meta.count`, заголовки бюджета); arXiv `GET /api/query?search_query=<head> AND
  submittedDate:[…]&max_results=1` (`opensearch:totalResults`).
- Чтение базы: `works` по `source`, `field`, `observed_at` (месяц / год), `min(observed_at)`.
- Вывод A2: `DATA_DIR/arxiv-version-dupes-<YYYY-MM-DD>.tsv` (колонки `works`).
- Окружение: `DATABASE_URL`, `OPENALEX_API_KEY`, `OPENALEX_FILTERS`, `ARXIV_CATEGORIES`.

## 11. Открытые вопросы

`OQ-06` (сверка по расписанию), `OQ-13` (расхождение чисел корпуса между документами —

выбор пользователя, не догадка; в `OQ-16` не входят.
