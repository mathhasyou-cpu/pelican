## 2. Краткое описание

ML-инженер докачивает векторы новых работ корпуса в файлы-шарды `EMB_DIR/shard-*.npz`,
чтобы научный поток конвейера (поиск 30 ближайших работ на фасет, FEAT-03) видел
свежие работы. Обход идёт всегда от самого свежего к старому, уже посчитанное
пропускается по id из самих шардов, прерывание рукой не теряет начатый шард. Шарды
читает конвейер напрямую или через шард-сервер на хосте.

## 3. Предусловия

- Корпус в `works` наполнен (UC-20 или UC-22).
- Сервер моделей запущен с эмбеддером `EMBEDDING_MODEL` (`config.Settings.embedding_model`)
  на `EMBEDDING_BASE_URL` или `LLM_BASE_URL`; GPU свободна.
- Каталог шардов `EMB_DIR` (по умолчанию `<DATA_DIR>/emb-science`) доступен на запись;
  знак `state.json`, если есть, записан той же моделью (иначе `SystemExit`:
  «смешивать векторы разных моделей нельзя»).
- Замок модели `locks.hold("model")` свободен: очередь запросов и перепрогоны его держат
  (`NFR-26`).

## 4. Триггер

В корпус добавлены работы без векторов (после UC-20/UC-22) или проверка полноты
показала, что векторов меньше, чем годных строк.

## 5. Основной поток

1. ML-инженер запускает докачку:

   ```bash
   python scripts/embed_science.py               # весь корпус, до Ctrl+C
   ```

2. Система берёт замок `model`, читает `state.json` (сверяет имя модели), собирает
   отсортированные id всех уже посчитанных работ из шардов (`vector_ids`, источник истины
   — файлы, а не знак), печатает «корпус N, уже посчитано M, осталось K, пакет B,
   следующий шард S».
3. Система читает страницы корпуса по `PAGE_ROWS` = 5000 строк в порядке
   `observed_at DESC, id DESC` с keyset-пагинацией (`page`), от самого свежего.
4. Для строк без вектора (двоичный поиск `_has_vector`) система отправляет пакеты по
   `EMBEDDING_BATCH_SIZE` (по умолчанию 64) на `/v1/embeddings` (`embed.embed`), тексты
   обрезаны до `MAX_CHARS` = 1500; ответы нормированы; вызов обёрнут `with_retries`.
5. Накопив `SHARD_ROWS` = 20 000 векторов, система пишет шард `shard-NNNNNN.npz`
   (`ids` int64, `vectors` float16, `model`, границы `since`/`until` внутри файла) через
   временное имя и `os.replace` (`flush`), номер — следующий свободный (`next_shard_index`),
   обновляет `state.json` (модель, глубина, `done`, `shards`) и печатает скорость, остаток
   часов, число пропущенных готовых за шард и за прогон.
6. Шаги 3–5 повторяются, пока корпус не кончится («корпус кончился») — код возврата 0.
7. Конвейер и шард-сервер читают новые шарды при следующем проходе (`weak.ground.nearest`),
   недописанный `.npz.tmp` маской `shard-*.npz` не находится.

## 6. Альтернативные потоки и потоки исключений

**A1. Наблюдение за прогоном.** Прогон почти нем (шард раз в минуты); ML-инженер
смотрит состояние отдельно:

```bash
python scripts/science_progress.py
```

Вывод: «векторы научного корпуса: done из total (%), шардов, глубина, последний шард
записан N мин назад», добор молодых срезов OpenAlex (UC-20) и суточный бюджет ключа
OpenAlex (один платный запрос, остаток — только из заголовков ответа). `collected_at` в
БД в UTC, печатаются оба времени.

**A2. Пробный прогон (шаг 1).** `--limit N` — посчитать не больше N строк за прогон
(проверка на малом объёме).

**A3. Замер пропускной способности (шаг 1).** `--measure` — прогрев и три размера
пакета (64/128/256) с печатью «текстов/с»; векторы не пишутся. Порог пакета подбирается
по замеру (`BR-49`).

**A4. Шард-сервер на хосте (шаг 7).** Для `api` в контейнере проход по шардам через
bind mount втрое медленнее (`shard_server.py`: ~165 с против ~60 с); администратор
запускает `python -m pelican.shard_server` на хосте — `127.0.0.1:` `SHARD_SERVER_PORT`
(по умолчанию 8020), `POST /top_k` (матрица float32 base64, `dim`, `k`, `as_of`) →
`ids`, `scores`; один проход за раз (`threading.Lock`); лог в `DATA_DIR/shard-server.log`.
`api` обращается к нему по `SHARDS_URL` (`host.docker.internal:8020`); не запущен —
`api` читает шарды сам (UC-27 A).

**E1. Прервано рукой (любой шаг).** `KeyboardInterrupt`: начатый шард дописывается
(«прервано рукой, дописываю начатый шард»), знак обновляется; следующий прогон начинает
снова от свежего и пропускает готовое по шардам.

**E2. Сетевая икота эмбеддера (шаг 4).** `with_retries` (`llm/client.py`) повторяет
пакет; исчерпание повторов роняет прогон — записанные шарды остаются.

**E3. Замок занят (шаг 2).** `locks.Busy`: печать «занято: …», код возврата **75**;
прогон не стартует, пока очередь или перепрогон держат модель.

**E4. Знак другой модели (шаг 2).** `state.json` записан другим `embedding_model`:
`SystemExit` с текстом причины; шарды двух моделей не смешиваются.

**E5. Строка добавлена в корпус позже с датой выше знака.** Не теряется: обход всегда
идёт от свежего, а пропуск готовых — по id из шардов, не по знаку (докстринг
`scripts/embed_science.py`, замер 2026-09-17: при знаке на 2023-07-27 3,96 млн строк выше
знака не имели вектора и при возобновлении по знаку не получили бы его никогда).

## 7. Постусловия

**Успех.** У каждой работы корпуса есть вектор ровно в одном шарде; `state.json` несёт
модель, глубину и счётчики; конвейер находит новые работы.

**Прервано.** Часть корпуса посчитана ровным временным срезом по обоим источникам (один
отсортированный поток, не «arxiv целиком, openalex пусто»); продолжение — тем же
запуском.

## 8. Особые требования

- `BR-49` (float16 и размеры страниц помечены: замер/догадка), `NFR-26` (замок модели),
  `NFR-32` (поиск по шардам — проход без индекса; шард-сервер втрое быстрее),
  `NFR-36` (`EMB_DIR`, `EMB_HOST_DIR`, `EMBEDDING_*`, `SHARDS_URL`), `NFR-47` (эмбеддер
  локальный), `NFR-48` (≈22 ГБ шардов), `NFR-56` (в контейнер шарды монтируются только на
  чтение).
- Префикс задачи EmbeddingGemma не применяется: векторы корпуса обязаны быть сопоставимы с
  векторами запросов (`embed_science.py` докстринг).
- Имя модели проверяется содержимым шарда (`model` внутри `.npz`), а не именем файла.
- Перед каждым прогоном окно GPU и замок `model` согласованы с администратором: докачка не
  идёт во время демо и очереди запросов.
- Номер шарда — счётчик свободных имён, не место во времени; границы дат лежат внутри
  файла (`since`/`until`), старые шарды без них читаются (`tests/test_weak_shards.py`).

## 9. Точки расширения и включения

- Следует за UC-20 и UC-22; входит в приёмку корпуса вместе с UC-30 (число векторов
  против числа годных строк).
- UC-03 (конвейер) и UC-25 (бэктест, `as_of` пропускает шарды целиком по границам дат) —
  потребители шардов.
- UC-27 A — запуск шард-сервера на хосте.

## 10. Данные и интерфейсы

- CLI: `python scripts/embed_science.py [--limit N] [--measure]`; коды 0 / 75 (замок).
- Файлы: `EMB_DIR/shard-NNNNNN.npz` (`ids` int64, `vectors` float16 768, `model`,
  `since`, `until`), `EMB_DIR/state.json` (`model`, `observed_at`, `id`, `done`,
  `shards`), `DATA_DIR/shard-server.log`.
- Константы: `SHARD_ROWS = 20_000`, `PAGE_ROWS = 5_000`, `MAX_CHARS = 1500`,
  `SOURCES = ("arxiv", "openalex")`, `config.embedding_batch_size = 64`,
  `config.llm_timeout_s = 180`, `shard_server.PORT` = `SHARD_SERVER_PORT` (8020).
- API шард-сервера: `POST /top_k` (`TopKIn {vectors, dim, k, as_of}` → `TopKOut {ids,
  scores}`), `GET /health`.
- Окружение: `EMBEDDING_MODEL`, `EMBEDDING_BASE_URL`, `EMBEDDING_API_KEY`,
  `EMBEDDING_BATCH_SIZE`, `EMB_DIR`, `EMB_HOST_DIR` (compose), `DATA_DIR`, `SHARDS_URL`,
  `SHARDS_URL_DOCKER`, `SHARD_SERVER_PORT`.

## 11. Открытые вопросы

`OQ-13` (14 млн векторов / 22 ГБ / 23,5 ГБ — расходятся), `OQ-16` (float16 — догадка).
