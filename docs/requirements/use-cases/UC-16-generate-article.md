## 2. Краткое описание

По ветке исследования аналитик заказывает аналитическую статью: что зарождается, на какой
стадии, что проверить банку. Модель пишет текст только по карточкам сигналов ветки; каждое
утверждение несёт сноску на источник карточки, предложение без опоры выбрасывается. Статья
читается с оглавлением, сносками, вставками-карточками, разделом «Что смотреть дальше» и
печатается в PDF. Тот же механизм пишет выпуск-дайджест темы после планового прогона (UC-18).
Ценность: результат нескольких прогонов — связный текст, который можно отдать коллегам,
не теряя проверяемости каждого факта.

## 3. Предусловия

- Ветка с ≥ 1 готовым отчётом (UC-15); статьи по ветке ещё нет (иначе — чтение).
- Исполнитель очереди и сервер моделей доступны; замок модели свободен или задание встанет
  в очередь.

## 4. Триггер

Аналитик нажимает «Написать статью» на странице ветки (UC-15 шаг 5). Для выпуска — UC-18
по условию BR-56.

## 5. Основной поток

1. Аналитик нажимает «Написать статью».
2. Система ставит в очередь задание `kind = 'article'` с `thread_id` и списком отчётов
   ветки (BR-57); кнопка показывает «Модель пишет статью…» и недоступна (A1 — ожидание в
   очереди).
3. Исполнитель (UC-03, ветвь для `kind = 'article'`) под замком модели собирает вход: по
   каждому сигналу ветки — `title, why, case, stage, confidence, sources[n]` из карточек;
   ничего, кроме карточек, в промпт не идёт (BR-53).
4. Система вызывает генеративную модель со строгой JSON-схемой ответа: `title`, `dek`,
   `sections: [{id, h, paras: [str], signals: [label]}]`, `watch: [str]`; сноска в тексте —
   `⟦k⟧`, `refs[k] = [label, n источника, имя отчёта]` (BR-29).
5. Система проверяет ответ по предложениям, переиспользуя проверки карточек
   (`weak/card.py`): `refs()` — у каждого предложения есть сноска и её `label`/`n` есть у
   сигнала ветки; `invented_numbers()` — чисел, которых нет в процитированных источниках,
   нет; `drop_foreign()` — чужое письмо снято. Предложение без опоры выбрасывается, а не
   исправляется; раздел без предложений выбрасывается.
6. Система проверяет ссылки сносок (http(s), источник существует в карточке — BR-24, BR-26)
   и сохраняет статью: `articles(id, kind 'thread', thread_id, reports, title, dek, body,
   refs, model, created)`; у ветки появляется `article_id`.
7. Система заканчивает задание; на странице ветки кнопка меняется на «Статья по ветке»,
   показывается тост.
8. Аналитик открывает статью (`#article=<id>`).
9. Система показывает: «← Ветка «<название>»», кикер «Статья по ветке исследования»,
   заголовок, подзаголовок, «<дата>», «N мин чтения», «по N отчётам», кнопки «Поделиться»
   и «Сохранить PDF»; слева — «Содержание» (разделы, «Что смотреть дальше», «Источники»).
10. Система показывает плашку: «Текст написан моделью <модель> только по карточкам сигналов
    из N отчётов ветки: каждое утверждение — со сноской на источник карточки, новых фактов
    модель не добавляет. Проверка ссылок — до публикации.» (BR-53, BR-28 — модель названа).
11. Система показывает разделы: абзацы со сносками-надстрочниками `k+1`; под разделом —
    вставки-карточки сигналов (значок стадии, стадия, уверенность, название, полоса,
    «Карточка в отчёте»), ведущие к карточке в отчёте нужного шага (UC-05).
12. Система показывает «Что смотреть дальше» (список) и «Источники»: для каждой сноски —
    название источника со ссылкой, «издатель, дата, тип; из карточки «<сигнал>», источник n»,
    и строку «Отчёты: <ссылки на отчёты ветки>».
13. Аналитик нажимает сноску — система прокручивает к источнику и подсвечивает его; клик по
    пункту содержания — к разделу.

## 6. Альтернативные потоки и потоки исключений

- **A1 (шаг 2). Очередь занята.** Задание статьи ждёт за прогонами (та же очередь, тот же
  замок); кнопка остаётся «Модель пишет статью…»; страница ветки при обновлении показывает
  то же состояние (статус задания).
- **A2 (триггер). Выпуск-дайджест темы.** Инициатор — UC-18 после планового прогона при
  `len(added) >= notify_min` и `write_article` (BR-56). Вход — карточки сигналов отчёта
  прогона плюс диф (`added`, `moved`, `gone`); статья `articles.kind = 'digest'`, `topic_id`,
  `reports = [отчёт прогона]`; задание очереди — то же `jobs.kind = 'article'` (BR-57). На экране: кикер «Выпуск темы «<запрос>»», «← Исследования» (или ветка,
  если тема привязана), полоса диф-чипов «+N появилось», «↗ N сменил стадию», «− N ушло»,
  разделы «Что появилось», «Что сменило стадию», «Что ушло»; в «Что смотреть дальше» —
  дата следующего прогона. Ушедшее описывается причиной из дифа, без сносок на источники
  (их у ушедшего сигнала в этом отчёте нет) — это единственное место без сноски, и оно
  помечено как диф, не как утверждение модели. Плашка выпуска (предложение; прототип
  показывает у выпуска текст статьи по ветке — «…из N отчётов ветки…», `research.js:
  renderArticle`): «Текст написан моделью <модель> только по карточкам сигналов отчёта
  прогона темы «<запрос>» и дифу с прошлым прогоном: каждое утверждение — со сноской на
  источник карточки, ушедшее — с причиной из дифа, без сноски. Проверка ссылок — до
  публикации.»
- **A3 (шаг 9). «Поделиться».** Копирует `#article=<id>` (UC-07, тот же механизм).
- **A4 (шаг 9). «Сохранить PDF».** `window.print()` с `@media print` экрана статьи. В
  прототипе (`shared/screens.css`, блок «печать статьи: только текст») скрываются шапка,
  оглавление, кнопки и тосты, сетка статьи становится одной колонкой, текст — 11 pt;
  `@page` в `shared/screens.css` задаёт A4, поля и номер «стр. / всего» внизу справа, а
  `research.js: renderArticle` вписывает в колонтитулы «АС ПЕЛИКАН, <заголовок>» и дату
  (правило `#article-page`, снимается при уходе с экрана) — как у отчёта в `print.html`
  (NFR-13).
- **A5 (шаг 12). Источник сноски не найден в карточке.** В «Источниках» строка
  «источник не найден»; такая сноска считается дефектом проверки шага 6 и попадает в лог.
- **E1 (шаг 4). Модель не ответила или ответила не по схеме.** Задание `failed` с
  `failure.explain`; кнопка возвращается в «Написать статью», тост с фразой отказа
  (BR-42).
- **E2 (шаг 5). После проверки не осталось ни одного предложения.** Статья не сохраняется;
  задание `failed` с текстом «Статья не написана: ни одно утверждение модели не опирается на
  источники карточек»; тост; аналитик может повторить.
- **E3 (шаг 8). Статьи с таким id нет.** «Такой статьи нет.»
- **E4 (шаг 1). Статья уже есть.** Кнопка — «Статья по ветке» (чтение); повторная
  генерация — отдельное действие (не предусмотрено прототипом; см. §11).

## 7. Постусловия

- **Успех:** строка в `articles`; у ветки (или прогона темы) ссылка на статью; статья
  открывается, печатается и делится ссылкой; каждое предложение тела несёт сноску на
  существующий источник карточки.
- **Отказ:** `articles` не изменена; задание `failed` с причиной; ветка без статьи.

  (`invented_numbers`, `IMPLEMENTATION.md` §6) в BR-53 не записано — BR-53 дополняется при
  DoR.
- NFR-01 (текст по-русски), NFR-06 (оглавление и статья без вложенной прокрутки; на узком
  экране оглавление над текстом), NFR-12 (сноски, вставки-карточки
  `#report=<name>&sig=<label>`, отчёты — ссылки; в прототипе вставка «Карточка в отчёте» —

  ручных запросов, в лимит «3 на адрес» не входит.

## 10. Данные и интерфейсы

Дельты (`IMPLEMENTATION.md` §6 «Статья»):

- Таблица `articles(id, kind 'thread'|'digest', thread_id, topic_id, reports TEXT[], title,
  dek, body JSONB, refs JSONB, model, created)`; `body` — `[{id, h, paras, signals}]`;
  `refs[k] = [label, n, report_name]`; дополнительно `watch TEXT[]`, `minutes INT` (оценка
  чтения) — поля прототипа, в плане не названы.
- Задание очереди: `jobs.kind = 'article'` (новая колонка) с `thread_id`/`topic_id`; идёт
  под `runner.MODEL_LOCK` после прогонов (BR-57).
- `GET /api/articles?thread=&topic=` → список `{id, kind, title, dek, created, minutes,
  thread_id, topic_id}`; `GET /api/articles/{id}` → статья целиком; `POST /api/threads/{id}/article`
  → 202 снимок задания (эндпоинт в плане не назван — предложение).
- Проверки: `weak/card.refs`, `weak/card.invented_numbers`, `weak/card.drop_foreign`,
  `weak/card.sentences` — переиспользуются без изменений; новая функция проверки статьи в
  `weak/article.py` (создать).
- Маршрут фронта: `#article=<id>`; печать — `@media print` экрана (прототип:
  `shared/screens.css` с `@page` и колонтитулами из `renderArticle`; A4).
- Подписи интерфейса (прототип): «Написать статью», «Модель пишет статью…», «Статья по
  ветке», «Статья по ветке исследования», «Выпуск темы «…»», «Содержание», «Что смотреть
  дальше», «Источники», «Карточка в отчёте», «Поделиться», «Сохранить PDF», «источник не
  найден», «Такой статьи нет.», «+N появилось», «↗ N сменил стадию», «− N ушло».

## 11. Открытые вопросы

- OQ-08.
- Повторная генерация статьи для ветки с новыми шагами: заменять, версионировать или
  запрещать — прототип не отвечает.
- Оценка «N мин чтения»: формула (слов / 200) — догадка, замер не нужен, но зафиксировать.
- Отдельный исполнитель для статей или ветвь UC-03.
- Прототип расходится с требованием (требование в силе): вставка-карточка — кнопка, а не
  ссылка (NFR-12); у выпуска темы плашка статьи по ветке вместо плашки выпуска (A2).
