## 2. Краткое описание

Аналитик пользуется прежним интерфейсом Streamlit: вводит направление, видит очередь и ход
выполнения, получает отчёт-документ (`/r/{name}`) во фрейме, скачивает его HTML,
открывает прошлые отчёты из истории. Ценность: страховка на время перехода и привычный
вид для тех, кто видел стенд раньше.

## 3. Предусловия

- Сервис `ui` запущен (`docker-compose.yml`: `streamlit run ui/app.py
  --server.baseUrlPath=classic`), `API_URL` указывает на `api:8010`.
- На стенде Funnel проксирует `/classic` → `http://ui:8501/classic` (`tailscale/serve.json`).

## 4. Триггер

Аналитик открывает `/classic` (на стенде) или `http://127.0.0.1:8501/classic` (локально).
Ссылки из руководства (UC-11) нет: пункт «Прежний интерфейс» снят из `Guide.jsx` вместе со
сценарием (`c1c4ea8`).

## 5. Основной поток

1. Система показывает заголовок «📡 Радар слабых сигналов» (ссылка на главную `./`),
   подпись о назначении (`st.caption`) и
   информационный блок `st.info`: одна локальная модель, запросы по одному, очередь,
   «15–20 минут», запрос из истории открывается без очереди (A1).
2. Аналитик вводит «Направление» и нажимает «Найти слабые сигналы» или одну из трёх кнопок
   примеров ТЗ («технологии в ИИ», «перспективные решения в финтехе», «слабые сигналы в
   области кибербезопасности»).
3. Система отправляет `POST /api/ask` с заголовком `X-Client-IP` = левый
   `X-Forwarded-For` (его ставит Funnel), иначе адрес соединения (`ui/app.py client_ip`).
4. Ответ 202 → система запоминает `job` в сессии, ставит `?job=<id>` в адрес и перерисовывает
   форму с неактивной кнопкой и спиннером; второй запрос из этой вкладки не запускается,
   пока первый в очереди или в работе.
5. Фрагмент «задание» обновляется каждые 3 с (`st.fragment(run_every="3s")`), запрашивая
   `GET /api/jobs/{id}`:
   - `queued` → полоса «В очереди: впереди N запрос(а) · начало ≈ M мин» (из `position`,
     `eta_start_s`): N = `position`, то есть вместе с идущим заданием (`jobs.status`:
     «идущий считается»).
     Подпись «Страницу можно не держать открытой: запрос запустится сам, ссылка на эту
     страницу сохраняет место в очереди»;
   - `running` → полоса «Идёт анализ · K мин», где K — минуты, прошедшие с `started`;
     `typical_run_s` (или 17 мин — литерал `17 * 60` в `job_panel`, равный
     `jobs.DEFAULT_RUN_S = 1020`) задаёт только длину полосы; раскрытый блок «Ход
     выполнения» с последними 15 строками `progress` (`ui/app.py job_panel`, срез
     `[-15:]`); полоса движется CSS-анимацией к 99 % за оставшееся время, не ступенькой.
6. `done` → «Готово»; система ставит `?report=<name>` и показывает отчёт: кнопка «Скачать
   отчёт (HTML)» (`<name>.html`) и `GET /r/{name}` во фрейме высотой по содержимому —
   прокрутка одна, у страницы.
7. Ниже — «История запросов»: `GET /api/reports` (последние 30, `api.reports`) кнопками
   «<запрос> — N сигналов, уверенных K · дата»; нажатие открывает отчёт (`?report=`).
   Справа — «Очередь»: `GET /api/queue`, строки «идёт: …» / «ждёт: …» или «пусто — новый
   запрос стартует сразу».

## 6. Альтернативные потоки и исключения

- **A1. Готовый отчёт.** На шаге 3 ответ 200 `cached` → система сразу показывает отчёт
  (`?report=<name>`), очередь не используется (BR-38).
- **A2. Прямые ссылки.** `?job=<id>` восстанавливает панель задания; `?report=<name>`
  открывает отчёт; полная загрузка без параметров начинает новую сессию, идущее задание в
  очереди не теряется.
- **A3. Задание не найдено** (`GET /api/jobs/{id}` ≠ 200) → ошибка «задание не найдено»,
  форма снова активна.
- **E1. Отказ постановки.** Ответ не 202 и не 200 (422 «запрос короче трёх символов», 429
  «с вашего адреса уже 3 запроса…») → текст `detail` показывается блоком ошибки, форма
  активна.
- **E2. Отказ прогона.** Статус `failed` → «Запрос не выполнен. <error>» и раскрывающийся
  блок «Подробности» с `error_detail` (BR-42); форма активна.
- **E3. Отчёт не найден** (`/r/{name}` ≠ 200) → предупреждение «отчёт не найден».
- **E4. История или очередь недоступны** (`httpx.HTTPError`) → пустые списки без ошибки.

## 8. Особые требования

- BR-36, NFR-51: Streamlit передавал адрес клиента заголовком `X-Client-IP`; API этот
  заголовок не читает — адрес берётся только из левого `X-Forwarded-For`, иначе адрес
  соединения (`api._client`, `c1c4ea8`).
- BR-42: фраза и «Подробности».
- NFR-30: опрос 3 с; история — `GET /api/reports`, 30 записей (маршрут снят, `c1c4ea8`).
- Отчёт-документ — страница `/r/{name}` (маршрут снят, `c1c4ea8`; HTML отчёта пишется в
  `reports.html` — `jobs.save_report`, — но пользователю не отдаётся); Streamlit ничего не вычислял и второй вид
  выдачи не рисовал.
- Базовый путь `classic`: Funnel отрезает `/classic` и подклеивает путь цели, поэтому
  Streamlit ждёт запросы под тем же префиксом (`docker-compose.yml`).
- Автотестов интерфейса нет (`tests/test_ui*.py` отсутствуют); поведение API, на которое он
  опирается, покрыто `tests/test_api.py`.
