## 2. Краткое описание

Отчёт хранит итог той версии конвейера, что его собрала: после правки раскрытия запроса,
денежного потока, оценки или карточек история показывает то, чего нынешний код уже не выдаёт.
ML-инженер обновляет отчёты истории на нужную глубину, не ломая ссылок: полный перепрогон
под тем же именем (`rerun.py`), переразметка только карточек без пересмотра отбора и порядка
(`recard.py`), пересчёт подписей ключевых предикторов без модели (`rescore.py`), причины
исключения и русские названия (`retext.py`) или импорт готовых отчётов с диска в таблицу
`reports` (`import_reports.py`). Все пять пишут через `jobs.save_report`: имя отчёта,
`reports.started` и ссылка `#report=<имя>` остаются прежними, сводка истории `summary`
пересчитывается, HTML отчёта пересобирается в `reports.html` (пользователю не отдаётся).

## 3. Предусловия

- Postgres доступен (`DATABASE_URL`), таблица `reports` заполнена (UC-03, UC-19, UC-26 `--tz`
  или прежний импорт).
- Для `rerun.py` и `recard.py`: сервер моделей, корпус и шарды на месте; замок
  `runner.MODEL_LOCK` свободен — очередь стенда пуста (исполнитель API при занятом замке
  получает `locks.Busy`, UC-03 E9).
- Для `rescore.py`: установлена модель роста `src/pelican/weak/growth.json` (UC-24) и
  обновлены подписи `weak/model.QUERY_LABELS` / `model.phrase`.
- Для `import_reports.py`: папка с парами `<имя>.json` + `<имя>.html` (формат `page.to_json`
  и `page.render`; такие пишут `measure_ask.py --tz` в `reports/ask/` и прежние версии
  `trends ask`).
- Если изменился состав выдачи — `weak/ask.REPORT_VERSION` уже повышен (NFR-61): перепрогон
  даёт отчёт новой версии, и повтор запроса снова открывает его как кэш (BR-38).

## 4. Триггер

Изменение конвейера: раскрытие запроса, денежный поток, оценка зрелости или порядок ТОП —
полный перепрогон; промпт карточки, углубление или русские резюме — переразметка карточек;
новая `growth.json` или подписи предикторов — пересчёт; перенос стенда или отчёты, посчитанные
до хранения в Postgres, — импорт. Также UC-28 («перепрогон отчётов после починки») и
`OQ-11` (история стенда после исправлений ревью).

## 5. Основной поток

1. ML-инженер выбирает глубину по тому, что изменилось (§4), и запускает перепрогон одного
   отчёта или всей истории:
   ```bash
   python scripts/rerun.py 20260924-221530
   python scripts/rerun.py --all
   ```
2. Система читает список отчётов (`jobs.reports(conn, limit=500)` — `--all` ограничен 500
   последними по `started`; более старые отчёты перепрогоняются только по именам, A4) и
   идёт **от старых к новым**: пометка «держится N из K» читает прогоны того же запроса,
   начатые раньше, и к этому моменту они уже пересобраны.
3. Для каждого имени система берёт строку `jobs.report(conn, name)` (нет — «отчёта нет»,
   дальше) и под `locks.hold(MODEL_LOCK)` выполняет полный `ask.run(store, row["query"])` с
   печатью прогресса — 15–20 минут на отчёт.
4. Система берёт прошлые прогоны того же запроса `jobs.history(conn, query)` — только
   `query`, `started` и `signals[].label` (`jsonb_path_query_array`), не полные JSONB — и
   `history.prior_runs(past, query, since)` с границей `since = started` **пересобираемого**
   отчёта (сам он и всё, что после, — не прошлое); `history.annotate` проставляет `held`,
   `history_runs`, `stable`.
5. Система рендерит `page.render(result)` и `page.to_json(result)` и пишет
   `jobs.save_report(conn, name, row["query"], row["started"], payload, html)`: имя и
   `started` прежние, `result`, `html` и `summary` новые; печатает «ТОП N за S с: …». Время
   фактического прогона — в самом результате (`result.started`, `seconds`).
6. ML-инженер проверяет на стенде: `#report=<имя>` открывается, строка истории (UC-09) стоит
   на прежней дате с новой сводкой, повтор того же запроса отдаёт
   готовый отчёт без очереди (BR-38), в карточках — «держится N из K» по новой истории.

## 6. Альтернативные потоки и потоки исключений

**A1. Переразметка карточек** (шаг 1) — `scripts/recard.py`: отбор, оценка, порядок и
уверенность не трогаются, меняются только тексты карточек, хронология, добранные источники
и русские резюме.
```bash
python scripts/recard.py 20260924-171913 --out reports/recard   # замер правки карточки
python scripts/recard.py --all --save                            # обновление истории
python scripts/recard.py --density reports/recard                # плотность по папке
```
Система восстанавливает свидетельства из источников сигнала (`Evidence(-1, …)` — как их
собрал `ask.run`), под `MODEL_LOCK` выполняет `deepen_top`, `write_cards`,
`russian_summaries` с `deadline=inf` (вне запроса бюджета заказчика нет — резюме дописываются
все); `--out` кладёт `ask-cards-<имя>-before.json` / `-after.json` для
`scripts/measure_card_facts.py --dir DIR --strict`; `--density` печатает на карточку: пустые
`description` / `advantage` / `case`, предложений, долю предложений с якорем (число или имя),
фактов хронологии, источников, пустых `why`, зарубежных источников без резюме. `--save`
пишет результат и страницу обратно тем же `save_report`.

**A2. Пересчёт подписей предикторов** (шаг 1) — `scripts/rescore.py`, без модели и прогона,
секунды на отчёт:
```bash
python scripts/rescore.py --all            # сухо: сверка уверенности, ничего не пишет
python scripts/rescore.py --all --save
```
Система восстанавливает пул скоринга — все `emerging` запроса до проверки тематичности:
`signals`, `thin` («за пределами ТОП») и исключённые с первой проверкой «другая отрасль»;
прогоняет тот же `ask.score(pool)`; **сверяет уверенность каждого сигнала с сохранённой**
(`TOLERANCE = 1e-6`) — совпала → меняет только строки `predictors` у `signals` и `thin` и
печатает «расхождение уверенности … ok; №1: …». Отчёт без предикторов (скоринга не было) —
«скоринга нет — пропуск».

**A2a. Причины исключения и русские названия** (шаг 1) — `scripts/retext.py`, без прогона:
```bash
python scripts/retext.py --all                      # сухо: сколько пустых причин и латинских названий
python scripts/retext.py --all --save [--no-model]
```
Исключённый с пустой причиной получает её из признаков оценки (`ask.excluded_why`, BR-03,
без модели); название без кириллицы в `signals`, `thin`, `watch`, `excluded` переводится
`ask.russian_titles` под `MODEL_LOCK` (NFR-01; `--no-model` — пропустить). Отбор, порядок,
имя и `started` не меняются; занято — код 75.

**A3. Импорт отчётов с диска** (шаг 1):
```bash
python scripts/import_reports.py ../reports/ask [--url <DATABASE_URL>]
```
Система применяет схему (`jobs.apply_schema`), для каждого `*.json` с парным `.html` читает
`query` и `started` (ISO, `astimezone()`), пишет `save_report(name=…)`: имя файла, если оно по
BR-45 (`YYYYmmdd-HHMMSS` или `tz-…-YYYYmmdd-HHMMSS`), иначе время его `started`
(`import_reports.report_name`, `tests/test_import_reports.py`); файл без
пары пропускается; повторный импорт того же имени перезаписывает строку; печатает «импортировано
отчётов: N». Так прогоны `measure_ask.py --tz` одного стенда становятся историей другого, и
карточки получают «держится N из K».

**A4. Выборочный перепрогон** (шаг 1) — имена через пробел вместо `--all`; порядок задаёт
ML-инженер (старые раньше новых, иначе `held` считается по непересобранным).

**E1. Замок модели занят** (шаг 3, A1, A2a). `locks.Busy` → «занято: …», код выхода 75 (как у
`measure_ask.py`). Замок берётся на каждый отчёт отдельно: между отчётами его может занять
очередь стенда. Первый же `locks.Busy` завершает весь скрипт (`rerun.py`, `recard.py`,
`retext.py` ловят его вокруг `main()`): отчёт, на котором замок занят, и все следующие не
обработаны, уже пересобранные записаны — повтор по именам оставшихся (A4).

**E2. Отказ прогона на одном отчёте** (шаг 3). `LLMError` или сетевой отказ прерывает
скрипт; уже пересобранные отчёты записаны, остальные остались прежней версии — повтор по
именам оставшихся (A4). Частичной записи одного отчёта нет: один `INSERT … ON CONFLICT`.

**E3. Пул скоринга не восстановился** (A2). Расхождение уверенности больше `TOLERANCE` →
«ПУЛ НЕ ТОТ — не пишу»; отчёт не трогается, причина — изменился состав пула в `ask.score`
или формат исключённых.

**E4. Отчёт старого формата** (шаги 3–5, A1–A2). `page.from_json` читает старые и новые
результаты (`tests/test_weak_ask.py::test_saved_report_reads_back_old_and_new`); у отчёта без
`history_runs` или `predictors` соответствующие поля появляются после обновления.

**E5. Имя не найдено** (шаг 3) — «отчёта нет», следующий.

**E6. Сводка истории** (шаг 5). `save_report` пересчитывает `summary` (`jobs.summary_of`);
у импортированных до появления колонки `summary` сводка дописывается при первом чтении
истории (NFR-63).

## 7. Постусловия

- Успех: строки `reports` обновлены под теми же `name` и `started`; `result`, `html`,
  `summary` — текущей версии конвейера (`REPORT_VERSION`); ссылки из истории, палитры и
  внешних сообщений работают; «держится N из K» пересчитано по пересобранным прошлым
  прогонам (перепрогон) или оставлено (переразметка, пересчёт).
- Отказ: часть отчётов обновлена, часть прежняя — видно по `result.started` и `models`
  каждого отчёта; история остаётся доступной, никакой отчёт не удалён.

## 8. Особые требования

- BR-45 (имя `YYYYmmdd-HHMMSS` и `reports.started` неизменны при перепрогоне), BR-38
  (после перепрогона отчёт версии ≥ `REPORT_VERSION` снова служит кэшем повтора), BR-13
  (K — прошлые прогоны того же запроса, до `HISTORY_RUNS = 5`, одинаковые наборы — одно
  наблюдение), BR-09/BR-10 (пересчёт даёт предикторы из того же разложения, уверенность не
  меняется — это и проверяется), BR-21/BR-22 (переразметка пишет карточки только по
  свидетельствам, цитата дословно), BR-28 (`models` в пересобранном результате — модели
  нынешнего прогона).
- NFR-01 (русские названия — A2a), NFR-26 (замок модели), NFR-33 (сводка хранится, не
  вычисляется при чтении), NFR-58 (отчёты бессрочно), NFR-61, NFR-62, NFR-63; BR-03
  (причина исключения из признаков оценки — A2a).
- HTML отчёта (`page.render`) пересобирается и пишется в `reports.html`, но пользователю не
  отдаётся: маршрут `/r/{name}` снят (`c1c4ea8`, NFR-02 «Снято»); отчёт открывается
  веб-интерфейсом из `result`.
- Перепрогон идёт от старых к новым; экспериментальные плечи (UC-26) в таблицу `reports` не
  пишутся и этим сценарием не обновляются.
- Скрипты принудительно переключают stdout в UTF-8: под перенаправлением консоль Windows
  даёт cp1251, и один символ «⚠️» валит прогон.
- Перед каждым обновлением: названо, что изменилось, и выбрана глубина; для изменения
  состава выдачи `REPORT_VERSION` повышен до перепрогона; для `--all` оценено время (число
  отчётов × 15–20 мин под замком модели), окно GPU и пустая очередь стенда согласованы; для
  пересчёта подписи `QUERY_LABELS` обновлены и первым идёт сухой прогон; для импорта папка
  содержит пары JSON + HTML одного формата, имена не пересекаются с отчётами стенда, кроме
  тех, что надо перезаписать.
