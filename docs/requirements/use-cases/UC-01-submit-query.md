## 2. Краткое описание

Аналитик вводит направление в свободной форме по-русски или выбирает один из трёх примеров
из задания и нажимает «Найти сигналы». Если по этому запросу уже есть готовый отчёт
текущей версии, он открывается без прогона («сразу» — слово подписи экрана; мерила задержки
нет: у `GET /api/reports/{name}` нет NFR на время ответа, проверка — ручная: тост и переход
на отчёт); если такой же запрос уже идёт или ждёт — аналитик
присоединяется к нему; иначе запрос встаёт в очередь, и аналитик попадает на экран
ожидания (UC-02). Ценность: один вход для любого направления, без ожидания там, где
результат уже есть.

## 3. Предусловия

- Веб-интерфейс открыт (`/`, сборка `web/dist` отдаётся API; `NFR-42`).
- API доступен; схема БД применена (`jobs.apply_schema`).
- Для открытия готового отчёта: в `reports` есть отчёт с тем же запросом и `version ≥ weak/ask.REPORT_VERSION` (= 2).

## 4. Триггер

Отправка формы запроса на главной (`Home.jsx`, форма `role="search"`), нажатие кнопки-примера
«Примеры из задания», либо команда палитры «Найти сигналы: …» (UC-10).

## 5. Основной поток

1. Аналитик открывает главную: надстрочник «Автоматизированная система поиска слабых
   сигналов», заголовок «Какое направление проверить на слабые сигналы?», лид «АС ПЕЛИКАН
   читает научные работы и новости о раундах, пилотах и сделках, находит технологии на
   ранней стадии и раскладывает их на радаре по зрелости.», поле «Например, перспективные
   решения в финтехе», кнопка «Найти сигналы», три примера из задания в порядке
   `Home.jsx EXAMPLES`: «перспективные решения в финтехе», «технологии в ИИ», «слабые
   сигналы в области кибербезопасности» (это первые три запроса из четырёх в
   `scripts/measure_ask.TZ_QUERIES`, где порядок иной — ИИ, финтех, кибербезопасность — и
   есть четвёртый «космические технологии и новые материалы», на главную не вынесенный),
   подпись «Новый запрос идёт около N минут, готовый по тому же запросу открывается сразу.
   Радар заполняется на глазах, вкладку можно закрыть: ссылка сохранит место.» (N — медиана
   длительности последних 20 отчётов истории, без истории — `jobs.DEFAULT_RUN_S = 1020`,
   `lib/timeline.js runText`), под ней — блок «Сейчас в работе» (`components/Active.jsx`,
   `id="active"`; очередь из `GET /api/queue`, показывается, только пока в ней есть свои
   задания, UC-09 A6) и блок «Последние отчёты» (до 6 карточек, UC-09).
2. Аналитик вводит текст и отправляет форму. Интерфейс отправляет форму только при длине
   обрезанного текста ≥ 3 (`required minLength={3}`, проверка в `onSubmit`); пока запрос
   отправляется, кнопка «Найти сигналы» и чипы примеров отключены, на кнопке — «Отправляю…»
   (`App.jsx startJob`, `sending`; `NFR-16`).
3. Интерфейс вызывает `POST /api/ask` с телом `{"query": <текст>}` (`lib/api.js ask`).
4. API схлопывает пробелы (`" ".join(query.split())`) и проверяет длину ≥ 3.
5. API ищет готовый отчёт того же запроса без учёта регистра с версией ≥ `REPORT_VERSION`
   (`jobs.cached_report`) — не найден.
6. API ищет активное задание (`queued`/`running`) с тем же запросом без учёта регистра
   (`jobs.active_job`) — не найдено.
7. API определяет адрес клиента (`api._client`: левый адрес `X-Forwarded-For`, иначе адрес
   соединения; других заголовков с адресом API не читает; `BR-36`) и ставит задание в хвост очереди (`jobs.enqueue`) под
   advisory-блокировками на текст запроса и на адрес; лимит `MAX_ACTIVE_PER_CLIENT = 3`
   активных на адрес не превышен.
8. API будит исполнителя (`worker.wake.set()`) и отвечает **202** со снимком задания
   (`jobs.snapshot`): `id, query, status: "queued", created, started, finished, progress[],
   error, error_detail, report, cancel, position, eta_start_s, typical_run_s`.
9. Интерфейс показывает тост «Запрос принят, задание <id>» и переходит на `#job=<id>` —
   экран ожидания (UC-02; `App.jsx startJob`). Обработка задания — UC-03.

## 6. Альтернативные потоки и исключения

**A1. Готовый отчёт (шаг 5).** Отчёт найден → API отвечает **200**
`{"status": "done", "query": <схлопнутый>, "report": <name>, "cached": true}`; интерфейс
показывает тост «По этому запросу уже есть отчёт — открываю его» и открывает отчёт в виде
радара, UC-04: переход идёт на `#report=<name>` с видом радара в памяти вкладки
(`App.jsx openReport` → `navTo(..., { view: "radar" })`, `nextOpts`), и экран отчёта сразу
дописывает вид в адрес (`Report.jsx reportHash`, `history.replaceState`) —
`#report=<name>&view=radar`. Отчёт версии ниже `REPORT_VERSION`
кэшем не считается — идёт основной поток (`BR-38`).

**A2. Тот же запрос уже активен (шаг 6).** API отвечает **202** со снимком существующего
задания (его `id`, `status`, `position`); дубль не ставится, лимит адреса не расходуется.
Интерфейс переходит на `#job=<id>` этого задания (`BR-39`).

**A3. Пример из задания (шаг 2).** Нажатие чипа отправляет его текст как запрос без ввода;
дальше — основной поток или A1.

**A4. Запрос из палитры (шаг 2).** Команда «Найти сигналы: <q>» (подсказка «N мин» — медиана
длительности отчётов истории в минутах, без истории — `DEFAULT_RUN_S`: `App.jsx items`,
`T.typicalRun`) при ≥ 3 символах — UC-10; дальше шаг 3.

**A5. Пустой адрес клиента (шаг 7).** Если адрес не определён (тесты, скрипты), лимит не
применяется (`jobs.enqueue`: «Пустой `client` не ограничен»).

**E1. Короткий запрос (шаг 4).** Длина < 3 после схлопывания → **422** с `detail`
«запрос короче трёх символов»; интерфейс показывает тост с этим текстом (`lib/api.js`
пробрасывает `detail` для 422/429). Клиентская проверка не даёт отправить такой запрос
из формы, но API защищён независимо (`BR-37`).

**E2. Лимит адреса (шаг 7).** У адреса уже 3 задания в `queued`/`running` → `jobs.Busy` →
**429** с `detail` «с вашего адреса уже 3 запроса в очереди и в работе — дождитесь, пока
один из них закончится»; тост с этим текстом (`BR-35`). Число 3 в тексте — подстановка
`jobs.MAX_ACTIVE_PER_CLIENT`. Если на экране есть блок «Сейчас в работе» (`#active`, главная),
интерфейс прокручивает к нему: там свои задания со ссылкой на экран ожидания, где ненужное
можно отменить (`App.jsx startJob`, UC-02 A7).

**E3. Сеть или 5xx (шаг 3).** Сбой `fetch` → тост «Нет связи с сервером. Проверьте сеть —
страница повторит сама.»; ответ 5xx → тост «Сервер ответил ошибкой <код>. Повторите через
минуту.» (`lib/api.js request`). Запрос не поставлен; флаг `asking` сброшен, повтор
возможен.

**E4. Исполнитель не запущен (шаг 8).** Приложение создано без исполнителя
(`create_app(runner=None)`) — задание ставится, но не стартует; видно по `/api/health`
(`worker: null`). В стенде не бывает; покрыто UC-28.

## 7. Постусловия

- **Успех (основной поток):** в `jobs` новая строка со статусом `queued`, `client` = адрес,
  `created = now()`; аналитик на `#job=<id>`.
- **Успех (A1):** новых строк нет; аналитик на `#report=<name>&view=radar`.
- **Успех (A2):** новых строк нет; аналитик на `#job=<id>` существующего задания.
- **Отказ (E1–E3):** состояние очереди не изменилось; показан тост с причиной.

## 8. Особые требования

- `BR-35` (лимит 3 на адрес), `BR-36` (адрес клиента), `BR-37` (≥ 3 символа),
  `BR-38` (кэш повтора по версии), `BR-39` (присоединение к активному), `BR-34` (один
  запрос за раз).
- `NFR-16` (тосты 422/429/5xx/сеть, защита от двойной отправки), `NFR-28` (один прогон),
  `NFR-51` (адрес клиента), `NFR-12` (примеры и отчёты — ссылки/кнопки, доступные с
  клавиатуры).
- Текст подписи и примеры — на русском (`NFR-01`).

## 10. Данные и интерфейсы

| Элемент | Значение |
|---|---|
| Эндпоинт | `POST /api/ask`, тело `{"query": str}` (`api.AskIn`) |
| Ответы | 200 `{status:"done", query, report, cached:true}`; 202 снимок (`jobs.snapshot`); 422 «запрос короче трёх символов»; 429 «с вашего адреса уже 3 запроса в очереди и в работе — дождитесь, пока один из них закончится» |
| Снимок задания | `id, query, status, created, started, finished, progress[], error, error_detail, report, cancel, position, eta_start_s`; `typical_run_s` — только у `queued`/`running` |
| `position` | ожидающих впереди + 1 за идущий; `eta_start_s` = остаток идущего (не меньше 60 с) + `typical_run_s` × ожидающих впереди |
| `typical_run_s` | медиана последних `jobs.HISTORY = 20` готовых заданий; пока их нет — `jobs.DEFAULT_RUN_S = 1020` |
| Константы | `jobs.MAX_ACTIVE_PER_CLIENT = 3`; `weak/ask.REPORT_VERSION = 2`; минимальная длина 3 (`api.ask`, `Home.jsx minLength`) |
| Таблицы | `jobs` (`query`, `status`, `client`, `created`), `reports` (поиск кэша по `lower(query)` и `result->>'version'`) |
| Блокировки | `pg_advisory_xact_lock(hashtext('q:' || lower(query)))`, `pg_advisory_xact_lock(hashtext(client))` |
| Фронт | `web/src/screens/Home.jsx`, `components/Active.jsx` (`GET /api/queue`), `App.jsx startJob`, `lib/api.js ask` |
