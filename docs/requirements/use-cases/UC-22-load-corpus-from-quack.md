## 2. Краткое описание

Вместо сбора с нуля (UC-20, часы сети и платный бюджет) ML-инженер переливает уже
собранный корпус из DuckDB, которую держит сервер Quack, в Postgres стенда: кусками по
диапазону id, с продолжением с места обрыва, с заменой `tech_mentions` целиком и
построением индексов корпуса в конце. Результат совпадает с новым сбором строка в
строку (id вычисляется из данных).

## 3. Предусловия

- Сервер Quack доступен по `quack:<хост>[:<порт>]`, токен задан (`--token` или
  `QUACK_TOKEN`).
- Postgres стенда доступен по `--url` или `DATABASE_URL`; на диске есть место под
  ≈14 ГБ базы с индексами (техдока §3).
- Таблица `works` пуста или содержит только строки прерванного перелива этим же скриптом.
  Продолжение идёт с `max(id)`, а id — хэш на всём диапазоне: одна работа, собранная UC-20,
  даёт большой `max(id)`, и все куски ниже него пропускаются — корпус заливается с дырой.
  Скрипт проверяет условие счётом на шаге 2 (E3).
- Установлен `duckdb` с расширениями `quack` и `postgres` (ставятся `INSTALL` при
  запуске; нужна сеть до репозитория расширений).
- Памяти клиента DuckDB хватает на один кусок: при `CHUNKS` = 32 это ≈475 тыс. работ и
  ~150 МБ текста (комментарий к `CHUNKS`, `OQ-16`); замера нет — при нехватке памяти
  `--chunks N` больше (A2).

## 4. Триггер

Развёртывается новый стенд или восстанавливается база, а корпус уже есть в исходном
хранилище.

## 5. Основной поток

1. ML-инженер запускает перелив:

   ```bash
   QUACK_TOKEN=... python -m pelican.load_corpus --from quack:localhost
   ```

2. Система применяет таблицы схемы без индексов (часть `schema.sql` до маркера
   `-- @indexes`), читает `max(id)` и `count(*)` уже залитого в `works` и `count(*)`
   научных работ (`source IN ('arxiv','openalex')`) в источнике через `quack_query`;
   печатает «источник: N работ; в Postgres уже M (до id D)». При `D > 0` сверяет M с числом
   научных работ источника с `id <= D` (E3).
3. Система открывает локальный DuckDB с `quack`, ставит `postgres`, делает
   `ATTACH <url> AS pg (TYPE postgres)`.
4. Система делит диапазон id `[0, 2^63)` на `CHUNKS` равных кусков (id — хэш, равномерен),
   пропускает куски с `hi <= max(id)` и начинает текущий с `max(id)`; каждый кусок — одна
   транзакция приёмника: `INSERT INTO pg.works (…) SELECT … FROM quack_query(…)` с
   вычислением `junk` на стороне источника (`_junk_sql`: `weak.corpus.JUNK_TYPES`,
   `MIN_TERM_CHARS`) и `field` из `payload_json`; значения не проходят через Python,
   запись — бинарным `COPY` расширения `postgres`.
5. После каждого куска система печатает «кусок i/CHUNKS: t с, всего M из N (T с)».
6. Система заменяет `tech_mentions` целиком (`DELETE` + `INSERT … SELECT` одним запросом,
   тысячи строк) и печатает их число.
7. Система строит индексы корпуса (`works_tsv` GIN по `tsv`, `works_observed`,
   `tech_mentions_tech`), выполняет `ANALYZE works`, `ANALYZE tech_mentions` и печатает
   время («индексы: T с»); код возврата **0**.

## 6. Альтернативные потоки и потоки исключений

**A1. Продолжение после обрыва (шаг 2–4).** Повторный запуск той же командой: куски до
`max(id)` пропускаются, текущий начинается с `max(id)` (`id > lo AND id <= hi`); ни дыры,
ни дублей (кусок — транзакция, порядок кусков — по возрастанию id) — при выполненном
предусловии «в `works` только строки перелива».

**A2. Иной размер куска (шаг 1).** `--chunks N` — больше кусков при нехватке памяти
клиента; меньше — при большом запасе.

**A3. Другой приёмник (шаг 1).** `--url postgresql://…` — Postgres не из настроек
(например, `pelican_test`).

**E1. Нет токена (шаг 1).** «нужен токен Quack: --token или QUACK_TOKEN», код возврата
**2**.

**E2. Отказ DuckDB / Quack / Postgres (шаги 2–7).** Скрипт выводит «отказ: …» и выходит
кодом **1**; залитые куски остаются (транзакции закрыты), продолжение — A1. `main` ловит
`duckdb.Error` и `psycopg.Error` (недоступный Postgres на шаге 2, `_pg_scalar` после куска,
построение индексов на шаге 7).

**E3. В `works` не только перелив (шаг 2).** Залитых строк не столько, сколько научных работ
источника с `id <= max(id)`: в таблице есть строки UC-20 или источник дописан после
обрыва. Скрипт выводит «отказ: в works M строк, а в источнике до id D — K: продолжение с
max(id) оставило бы дыру…» и выходит кодом **1**, ничего не заливая; лечится очисткой
`works` и переливом заново.

**E3. Запрос к нескольким таблицам присоединённой базы.** Не используется по построению:
источник читается через `quack_query` (сервер считает запрос у себя), а не `ATTACH`, из-за
ограничения «Multiple streaming scans» (`quack.py`).

**E4. Обрыв на построении индексов (шаг 7).** Индексы идемпотентны
(`CREATE INDEX IF NOT EXISTS`); повторный запуск пропустит куски и достроит индексы.

## 7. Постусловия

**Успех.** `works` содержит все научные работы источника (count совпадает с «источник: N
работ»), `junk` и `field` посчитаны, `tech_mentions` заменена, индексы корпуса построены
и собрана статистика; `collected_at` у перелитых строк NULL (дата сбора неизвестна,
`NFR-60`). Векторов нет — далее UC-21; полнота по месяцам — UC-30.

**Обрыв.** Префикс диапазона id залит целиком; продолжение тем же вызовом.

## 8. Особые требования

- `FEAT-31` (перелив из Quack — часть функции сбора корпуса).
- `BR-49` (`CHUNKS` — догадка, `OQ-16`), `NFR-41` (таблицы на старте, индексы — переливом),
  `NFR-57` (схема), `NFR-59` (перелив совпадает с новым сбором строка в строку — одна
  функция `work_id` и один md5), `NFR-60` (`collected_at`).
- Индексы корпуса строятся один раз после заливки: GIN, обновляемый на каждой вставке,
  на 15 млн строк дороже (`schema.sql`); настройки Postgres в `docker-compose.yml`
  (`maintenance_work_mem` 2 ГБ, параллельные воркеры) рассчитаны на это (`NFR-48`).

## 9. Точки расширения и включения

- Альтернатива UC-20 для получения корпуса; далее UC-21 (векторы) и UC-30 (полнота).
- Используется UC-27 при развёртывании стенда с полным корпусом.

## 10. Данные и интерфейсы

- CLI: `python -m pelican.load_corpus --from quack:<хост>[:<порт>] [--token T] [--url U]
  [--chunks N]`; коды 0 / 1 (DuckDB) / 2 (нет токена).
- Константы: `load_corpus.CHUNKS = 32`, `ID_SPAN = 2**63`, `SCIENCE = ('arxiv',
  'openalex')`; `weak/corpus.JUNK_TYPES`, `MIN_TERM_CHARS`.
- Источник: таблицы `signals` (id, source, term_raw, observed_at, url, payload_json) и
  `tech_mentions` в DuckDB за сервером Quack; доступ `quack_query(dsn, sql,
  disable_ssl := true, token := …)` (`quack.relation`).
- Приёмник: `works`, `tech_mentions` (`schema.sql`); индексы за `-- @indexes`.
- Окружение: `QUACK_TOKEN`, `DATABASE_URL`.
