## 2. Краткое описание

Аналитик читает встроенное руководство: что делает АС ПЕЛИКАН, как формулировать запрос,
что происходит во время поиска, как читать радар и карточку, что и почему исключено, как
поделиться, какие клавиши. Иллюстрации — живые детали продукта: радар последнего отчёта из
истории, мини-мишени стадий, список стадий с типичным временем. Ценность: пользователь
понимает выдачу без внешней документации.

## 3. Предусловия

- Веб-интерфейс открыт. Для иллюстрации радара нужен хотя бы один отчёт в истории; без
  него раздел показывается без иллюстрации.

## 4. Триггер

Кнопка «?» («Руководство») в шапке, команда «Руководство» в палитре (UC-10), ссылка «Как
читать отчёт» в подвале отчёта (UC-04, ведёт на `#guide=card`) или адрес `#guide[=раздел]`.

## 5. Основной поток

1. Аналитик открывает `#guide`.
2. Система показывает «Открываю руководство», берёт самый новый отчёт истории
   (`app.sorted[0]`; если история ещё не загружена — `loadHistory()` и первый по `started`)
   и запрашивает его целиком `GET /api/reports/{name}` для иллюстрации.
3. Система показывает заголовок «Как работать с АС ПЕЛИКАН», подзаголовок «Пять минут
   чтения…», оглавление и восемь разделов в порядке: «Что делает АС ПЕЛИКАН» (`start`),
   «Как спросить» (`ask`), «Пока идёт поиск» (`wait`), «Как читать радар» (`radar`),
   «Карточка сигнала» (`card`), «Что исключено и почему» (`cut`), «PDF, ссылка, история»
   (`share`), «Клавиши» (`keys`).
4. Содержание разделов:
   - `start`: определение слабого сигнала (учёные пишут, деньги идут, массового внедрения
     нет), четыре шага «Запрос → около N минут → Отчёт → Дальше (PDF, ссылка коллеге,
     история)»; N — `T.runText` (медиана истории, без неё 17).
   - `ask`: лучше отрасль или задача, не компания и не одно слово; система раскроет запрос в
     4–6 направлений — секторы радара; примеры «Хорошо» (перспективные решения в финтехе;
     антифрод на устройстве клиента; платёжные системы для ИИ-агентов) и «Хуже» («ИИ — слишком
     широко, топ займут категории», «Visa — компания, а не технология», «блокчейн 2021 —
     АС ПЕЛИКАН смотрит на сегодня»).
   - `wait`: около N минут, по одному, очередь с местом, вкладку можно закрыть; список
     десяти стадий из `web/src/lib/timeline.js` с оценочным временем стенда (`T.BASE` —
     неизменяемая копия; медианы `T.setTypical` меняют только `T.STAGES` экрана ожидания);
     «Полоса прогресса поделена по
     типичной длительности этапов на последних прогонах — это не прогноз…»; «С одного адреса в
     работе и в очереди может быть не больше трёх запросов».
   - `radar`: живой радар отчёта-образца с подписью «Радар отчёта «<запрос>»»; пояса —
     стадия (в центре раннее внедрение, у края концепция), секторы — направления с буквами,
     точка — сигнал (номер, размер по источникам, заливка — уверенность, жёлтая выше 75 %),
     за кругом — исключённое, пунктир — вне топа; оговорка об условном секторе у старых
     отчётов.
   - `card`: уверенность модели роста с предикторами, «Почему это слабый сигнал» со ссылками
     [1][2], стадия с четырьмя мини-мишенями (`lib/stages.js`), кейс для банка и гипотеза,
     свёрнутые проверки, хронология, след в корпусе, источники; пометка «машинное резюме».
   - `cut`: пять классов с пояснениями: зрелое, стандарт, хайп, шум (в том числе
     свидетельства не о предмете — соответствие ниже 2 по шкале 0–3), слишком общее.
   - `share`: «Сохранить PDF», «Поделиться» (тот же вид, выбранный сигнал, раскрытое
     исключённое), «История», «Повтор запроса» (готовый открывается сразу).
   - `keys`: Ctrl/⌘+K, `/`, ↑↓←→ («листать сигналы в отчёте»), Enter («открыть карточку
     строки стола»), Esc.
5. Аналитик нажимает пункт оглавления → система прокручивает к разделу
   (`Guide.jsx jump`: плавно, при `prefers-reduced-motion` — сразу; NFR-10) и меняет адрес на `#guide=<id>` (`history.replaceState`); при прокрутке текущий раздел
   в оглавлении подсвечивается (IntersectionObserver).

## 6. Альтернативные потоки и исключения

- **A1. Прямая ссылка на раздел.** `#guide=card` → после отрисовки система прокручивает к
  разделу `g-card` без анимации.
- **A2. Отчётов нет.** История пуста или образец не загрузился → раздел «Как читать радар»
  показывается без иллюстрации и подписи; остальное без изменений.
- **A3. Образец берётся один раз** на вход в руководство; новый отчёт, появившийся во время
  чтения, не подменяет иллюстрацию.
- **E1. Ошибка загрузки истории или отчёта** приравнивается к A2 (руководство не падает).

## 8. Особые требования

- NFR-64 (руководство — экран продукта), NFR-03 (термины руководства согласованы с

  формулировки повторяются, и при изменении HINTS правится вместе), NFR-06 (страница
  прокручивается целиком; оглавление без собственной прокрутки), NFR-12 (ссылки оглавления —
  `<a href="#guide=…">`).
- BR-44: список стадий в разделе `wait` берётся из `timeline.js`, копии стадий
  `events.RUN_STAGES`, которую сверяет `tests/test_events.py`.
- BR-35: текст «не больше трёх запросов» соответствует `jobs.MAX_ACTIVE_PER_CLIENT = 3`.
- Длительность в разделах `start` и `wait` — `T.runText` по истории, без неё
  `DEFAULT_RUN_S = 1020` (копия `jobs.DEFAULT_RUN_S`).
- Раскладка `.guide` (`screens.css`): две колонки — оглавление 220 px (липкое под шапкой)
  и текст до 760 px; на ширине ≤ 960 px — одна колонка, оглавление статично, пунктами в
  строку с переносом.
- Прототип содержал ещё разделы `deep`, `article`, `topics` (этап 6); в реализации их нет
  (`OQ-08`).
