## 2. Краткое описание

ML-инженер прогоняет оценку зрелости конвейера на датасете методолога (100 положительных
строк) и контрольном наборе (30 строк классов исключения ТЗ) и получает воспроизводимый
отчёт `reports/weak-eval.md` с Precision, Recall, F1, specificity и 95 % интервалами, точностью
стадии против рубрики и оговорками. Это промежуточная сдача по ТЗ и число, которым жюри
судит обнаружение сигнала. Отчёт пересчитывается из TSV замера, а не пишется руками, поэтому
не может разойтись с замером.

## 3. Предусловия

- Корпус в Postgres наполнен (UC-20 или UC-22), GIN-индекс построен; шарды векторов доступны
  (UC-21) — для плеч `corpus` и `issue` и для признаков `E`.
- Сервер моделей запущен с `google/gemma-4-12b-qat` и `google/embedding-gemma-300m`
  (`LLM_MODEL`, `EMBEDDING_MODEL`).
- Датасеты на месте: `scripts/weak_signals_100.tsv` (100 строк методолога; заголовок
  `n tech domain companies why stage trend score sources` — номер, технология, домен,
  компании, обоснование, стадия развития, тренд упоминаний, балл стадия + тренд, источники),
  `scripts/weak_controls.tsv` (30 контрольных).
- Установлены зависимости `pip install -e ".[dev,ml]"`.
- Замок модели `runner.MODEL_LOCK` свободен (очередь стенда не идёт): скрипты этого сценария
  держат замок на весь прогон и при занятом выходят кодом 75 (E2).

## 4. Триггер

Изменение конвейера оценки (`weak/assess.py`, промпт, состав свидетельств), подготовка сдачи
или ответ на `OQ-11` (перемер после исправлений ревью).

## 5. Основной поток

1. ML-инженер выбирает плечо свидетельств: `papers` (только работы), `mixed` (работы +
   новости), `corpus` (mixed + след корпуса), `issue` (состав выдачи: 5 новостей + 2 работы +
   след) и запускает замер:
   ```bash
   python scripts/measure_signal_kinds.py --evidence mixed
   python scripts/measure_signal_kinds.py --evidence corpus --features-out --embed-features
   ```
2. Система для каждой из 130 строк привязывает название к корпусу, переводит, собирает
   свидетельства плеча и вызывает оценку зрелости `weak.assess` — модели показываются только
   название и свидетельства, ни стадия, ни обоснование методолога.
3. Система считает: долю `emerging` среди положительных (recall) и среди контроля (ложные
   срабатывания), матрицу «ожидали → получили» по контролю; стадию против «Стадия развития»
   (`weak.rubric.parse_stage`): точно и в пределах соседней ступени. Сравнивается ступень
   выбора модели (`stage` оценки), а не ступень выдачи: лестницу вех `rubric.evidence_stage`
   применяет `weak.ask` после скоринга (UC-03), `measure_signal_kinds.py` её не вызывает
   (на одном TSV плеча `mixed`, 99 строк: лестница — точно 30, ±1 61; выбор модели — 29 / 57,
   `docs/weak-measurements.md` в корне репозитория, `3f5dc56`); тренд и балл против
   колонок методолога, сравнивая с долей большинства (63 %), а не с 50 %.
4. Система пишет `reports/weak-assess-<плечо>.tsv` (с `--features-out` — также
   `reports/weak-features-<плечо>.tsv` для UC-31; с `--embed-features` —
   `reports/weak-label-vectors-<плечо>.npz`).
5. ML-инженер собирает отчёт:
   ```bash
   python scripts/weak_eval_report.py        # → reports/weak-eval.md
   ```
6. Система пересчитывает из TSV всех плеч: воспроизводимость рубрики (98 из 100), Precision,
   Recall, F1, Accuracy, Specificity с интервалами Уилсона, TP/FN/FP/TN, стадию, смещение
   стадии, промахи по положительным, матрицу контроля; вписывает обязательные оговорки.
7. ML-инженер читает отчёт и, если числа изменились, обновляет техдоку §10 и Vision §7.

## 6. Альтернативные потоки и потоки исключений

**A1. Оценка точности ТОП независимым судьёй** (шаг 7). Полнота по датасету не говорит, какая
доля наших карточек хороша. ML-инженер судит карточки живых прогонов (`ask-cards-*.json`
из `measure_ask.py --domains`) LLM-судьёй:
```bash
python scripts/judge_precision.py --sample 20                      # карточки на ручную разметку
python scripts/judge_precision.py --check                          # согласие судьи с рукой
python scripts/judge_precision.py --dir reports                    # своя модель (верхняя граница)
python scripts/judge_precision.py --dir reports --model gigachat3.1-10b-a1.8b   # независимый судья
```
Судье не показываются `kind`, `stage`, уверенность, позиция; довод «против» пишется раньше
вердикта; вердикт вне словаря из пяти классов отбрасывается. Пробы снисходительности — чужой
домен (обязан дать `offtopic`) и снятые нашей моделью. Согласие с ручной разметкой ниже 80 %
→ число объявляется оценкой сверху. Итог — `judge-precision.tsv/json` рядом с прогоном
(свидетельство создаётся на машине стенда и в репозиторий не входит (`.gitignore: reports/*`);
проверка — по имени файла и дате на стенде); расхождение двух судей (96 % своя модель против
84 % GigaChat) — мера self-preference bias.

**A2. Покрытие списка методолога по направлению** (шаг 7). `judge_match.py` сопоставляет
каждое название ТОП со всеми строками датасета домена (судья видит только названия):
```bash
python scripts/judge_match.py --check            # 14 ручных пар, scripts/judge_pairs.tsv
python scripts/judge_match.py --dir reports      # judge-coverage.tsv
```
Согласие на 14 парах (13 из 14) — условие, при котором судья становится метрикой.

**A3. Трудный контроль** (шаг 1). Лёгкий контроль очевиден; ML-инженер собирает трудный из
собственной выдачи: `make_hard_controls.py` берёт карточки с ручным «нет» из
`scripts/precision_pairs.tsv`, кандидатов по зрелому ядру (`MATURE_WORKS = 3000`,
`MATURE_SINCE = 2019` — догадка) в `reports/hard-control-candidates.tsv` на глаза человеку и
вердикты судьи `mature`/`market`; провенанс пишется колонкой `откуда`. Затем:
```bash
python scripts/measure_signal_kinds.py --evidence mixed --controls-file scripts/weak_controls_hard.tsv
```

**A4. Метка «вошёл в список заказчика»** (шаг 7). `label_listed.py --dir reports/bt-<срез>`
размечает тем же судьёй весь пул кандидатов среза (ТОП + снятые + с одним игроком) и
дописывает столбец `listed` в `backtest-classifier.tsv` — вход для UC-24 с исходом `listed`.

**A5. Разметка закрытого датасета** (шаг 1). Для датасета организаторов неизвестного формата:
```bash
python scripts/predict_dataset.py <датасет.csv> --out reports/predictions-<имя>.csv [--vote any|corpus]
```
Формат угадывается по заголовку и печатается первой строкой. В CSV: `is_weak_signal`, `kind`,
`stage`, `checks_share`, `probability` (модель этапа 1, пусто без выполненного правила), `why`,
`sources`. Балла стадия+тренд в выходе нет (BR-11).

**A6. Сравнение локальной модели с облачной** (шаг 1, STR-14). Генерация — `sonar`,
эмбеддинги — локальные; результат пишется в свой файл `reports/weak-assess-mixed-sonar.tsv`,
локальный замер не перезаписывается (`docs/final-measure.md` §3). Подписывается как верхняя
граница: sonar сам ищет в интернете.

**E1. Сервер моделей недоступен или модель не загружена** (шаг 2). Замер прерывается с
`LLMError`; строки до отказа в TSV не считаются результатом — прогон повторяется целиком.

**E2. Замок модели занят** (шаг 1). Скрипты оценки — `measure_signal_kinds.py`,
`judge_precision.py`, `judge_match.py`, `predict_dataset.py`, `label_listed.py` — держат
`runner.MODEL_LOCK` на весь прогон (`NFR-26`): при идущем задании очереди скрипт сразу
выходит с «занято: …» и кодом 75. Так же замок берут `measure_ask.py`, `retro_hits.py`
(UC-26), `measure_arms_tz.py` (UC-26), `embed_science.py` (UC-21), `rerun.py`, `recard.py`,
`retext.py` (UC-29), `backtest_classifier.py` (UC-25): у них занятый замок — `locks.Busy`,
код 75.

**E3. Отладка на подвыборке** (шаг 1). `--limit N --controls M` — числа в отчёт не идут.

## 8. Особые требования

- BR-01, BR-02 (класс решает модель по свидетельствам), BR-14 (четыре ступени), BR-11 (тренд
  и балл не выводятся), BR-49 (пороги — замером), BR-52 (интервалы и кто размечал).
- NFR-26 (замок модели у замеров, E2), NFR-39 (тесты), NFR-44, NFR-66
  (отчёт из TSV, не руками).
- Предел различимости считается до прогона: на 100 положительных при 0.80 — ±0.078; на 30
  контрольных при 0.10 ложных — ±0.11. Разница между правками меньше интервала результатом
  не является.
- Контроль написан по-русски в манере положительных, иначе классы делятся по языку и стилю.
- Перед каждым замером: ожидаемая разница правки больше предела различимости (иначе замер не
  ставится); датасеты не изменены с прошлого замера либо изменение описано; версия конвейера
  оценки зафиксирована коммитом, прошлые TSV сохранены под другим именем, если нужно «до/после»;
  для A1 независимый судья доступен по `LLM_BASE_URL`; для A6 ключ облака и бюджет (~$0.7 за
  плечо) согласованы; замок модели и окно GPU согласованы (130 строк × плечо — порядка 15 мин
  локально).
