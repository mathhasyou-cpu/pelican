## 2. Краткое описание

ML-инженер обучает модель, которая в выдаче даёт «уверенность модели», ключевые предикторы и
порядок ТОП (BR-08, BR-09): L1-логистическую регрессию с калибровкой Platt на признаках,
нормированных внутри запроса (установленная модель после L1 держит один —
`query_share_pct`), с целью «вырастет ли научный след ядра за два года
сильнее медианы области». Обучение идёт на срезах бэктеста (UC-25), проверяется будущим
(temporal holdout) по правилу, записанному до прогона, и устанавливается в
`weak/growth.json` только при выполненном правиле.

## 3. Предусловия

- Срезы готовы (UC-25): `reports/bt-2020-09-15`, `bt-2022-09-15`, `bt-2024-09-15` с
  `backtest-classifier.tsv` (признаки на срезе, исходы, `gemma на срезе`); посчитаны на одном
  горизонте `HORIZON_YEARS = 2` и одном наборе срезов корпуса.
- Для исхода `listed` — столбец `listed` дописан (`label_listed.py`, UC-23 A4).
- Установлены `.[ml]` (scikit-learn, scipy).
- Признаки в TSV совпадают с контрактом `weak/model.QUERY_FEATURES`
  (`tests/test_weak_model.py::test_shipped_growth_params_match_feature_contract`).

## 4. Триггер

Новый срез бэктеста, изменение признаков `weak/model.py`, изменение цели (деньги, список
заказчика), подозрение на дрейф эпохи.

## 5. Основной поток

1. ML-инженер выписывает правило зачёта до прогона (докстринг скрипта): на test LODO-AUC ≥ пола
   случайности И ≥ AUC ТОП конвейера на том же исходе И ≥ одиночного momentum ядра И медиана
   прироста верха модели (того же размера, что ТОП, по доменам) ≥ медианы верха конвейера.
   Ожидание: 0.70–0.78.
2. ML-инженер запускает обучение модели скоринга выдачи с temporal holdout на пуле двух срезов
   и проверкой на третьем — все три фолда:
   ```bash
   python scripts/train_growth_model.py --in-query \
       --dir reports/bt-2022-09-15,reports/bt-2024-09-15 --test-dir reports/bt-2020-09-15 --holdout-tag pool-to-2020
   python scripts/train_growth_model.py --in-query \
       --dir reports/bt-2020-09-15,reports/bt-2024-09-15 --test-dir reports/bt-2022-09-15 --holdout-tag pool-to-2022
   python scripts/train_growth_model.py --in-query \
       --dir reports/bt-2020-09-15,reports/bt-2022-09-15 --test-dir reports/bt-2024-09-15 --holdout-tag pool-to-2024
   ```
3. Система берёт пул скоринга — только `emerging` по gemma на срезе (фильтр мейнстрима стоит до
   скоринга, как в `weak.ask`), считает `QUERY_FEATURES` внутри каждого запроса той же функцией
   `query_features`, что в выдаче; из обучения и проверки убирает строки без исхода — база ядра
   меньше `backtest_classifier.MIN_BASE` работ (`with_outcome`, после `in_query`); выбирает
   набор признаков (`Q` или `Q+C`) по LODO (`GroupKFold` по домену) на train; рядом печатает стратифицированную CV (разрыв — утечка домена) и пол случайности
   (95-й перцентиль AUC при перестановке).
4. Система отбирает устойчивые по знаку признаки между обучающими срезами (`stable_features`,
   `STABLE_MIN_GAP = 0.10`), применяет парсимонию (`pick_best`: L1, если не хуже L2 на
   `L1_MARGIN = 0.02`), калибрует Platt; печатает базовые линии на тех же строках: ТОП конвейера,
   модель этапа 1, gemma, одиночные `players`, `core_momentum`, `low_visibility`.
5. Система проверяет на test, пишет `reports/weak-growth-holdout.in-query.<tag>.md/.json`
   (стем `weak-growth-holdout`, `.in-query` при `--in-query`, `.<tag>` при `--holdout-tag`)
   с вердиктом по правилу.
6. ML-инженер сверяет все три фолда (базовая линия: AUC 0.83 ± 0.09 / 0.90 ± 0.06 /
   0.83 ± 0.07 на проверочных срезах 2020 / 2022 / 2024 против 0.78 / 0.77 / 0.80 у одного
   роста ядра, 0.68 / 0.74 / 0.64 у ТОП конвейера и 0.61 / 0.60 / 0.60 случайно; выбран
   `lr_l1 / Q`, на test 79 / 117 / 116 строк — `reports/weak-growth-holdout.in-query.pool-to-*.md`,
   техдока §5 шаг 7). От одного роста ядра модель отличается внутри интервала.
7. При выполненном правиле на всех фолдах ML-инженер обучает финальную модель на всех трёх
   срезах и устанавливает её:
   ```bash
   python scripts/train_growth_model.py --in-query \
       --dir reports/bt-2020-09-15,reports/bt-2022-09-15,reports/bt-2024-09-15 --install
   ```
   Система пишет `src/pelican/weak/growth.json` (веса, подписи `QUERY_LABELS`, калибровка); в
   выдаче вероятность становится «уверенностью», слагаемые — предикторами.
8. ML-инженер обновляет техдоку §5 шаг 7 и §7 (веса установленной модели: C = 0.1, 312 строк
   с исходом; единственный ненулевой вес — «публикации свежее, чем у других кандидатов
   запроса», `query_share_pct`, +1.37; «доля публикаций за последний год», «за технологией
   стоят компании», число компаний — обнулены L1) и запускает `pytest`.

## 6. Альтернативные потоки и потоки исключений

**A1. Исход «рост публикаций ИЛИ денег»** (шаг 2) — `--outcome grew_or_money` с набором `Q+C`
(коммерческая стадия по чтениям). Правило: тот же гейт на всех трёх фолдах И на test не хуже
нынешней `growth.json` на тех же строках (скрипта сравнения в репозитории нет — он упомянут
только в докстринге `train_growth_model.py`; сравнение делается по отчётам holdout вручную).
Базовая линия:
коммерческая стадия будущий рост не предсказывает лучше научных признаков — модель её не
использует: на исходе «рост следа» `Q+C` не лучше `Q` ни на одном фолде (0.83 / 0.91 / 0.82
против 0.83 / 0.90 / 0.83, `docs/weak-audit.md` в корне репозитория, `042fde6`). Отчёты исхода
`grew_or_money` (`reports/weak-growth-holdout.in-query.money-*`, 28.09.2026) посчитаны до
перепрогона срезов; на пулах с научным потоком этот исход не перемерен (техдока §7, денежный
след бэктеста снят `--no-money`, UC-25).

**A2. Модель денег** (шаг 2) — `--outcome money_grew|money_top`, наборы `$`, `I`; правило плюс
одно: LODO-AUC ≥ лучшей одиночной денежной линии + `MONEY_MARGIN = 0.03`; иначе «деньги
предсказываются только деньгами». Артефакт `src/pelican/weak/money.json` (`MONEY_INSTALL`),
отчёт `reports/weak-money-model.*` / `weak-money-holdout.*`.
Ожидание 0.65–0.75.

**A3. Модель списка заказчика** (шаг 2) — `--outcome listed` (PU-обучение; метка из
`label_listed.py`). Правило — hits@k: строк списка в верхе модели ≥ верха линии
`core_last_year_share` И ≥ верха старого ТОП. Не побита — `weak/listed.json` не ставится
(базовая линия: выключена, `WEAK_LISTED_IN_ASK` не задан; вживую 22 против 23 строк и 210–390 с
на запрос).

**A4. Абсолютные признаки** (шаг 3) — без `--in-query`, наборы `M`, `M+J`, `M+J+N`, `M+J+N+E`,
`S` на всех кандидатах (не только `emerging`). Базовая линия: выбран `lr_l1 / S`, AUC 0.90 /
0.90 / 0.81 на проверочных срезах 2020 / 2022 / 2024 при поле 0.56 / 0.57 / 0.56
(`reports/weak-growth-holdout.abs-pool-to-*.md`). Пулы другие (на test 220 / 239 / 253 —
все кандидаты против 79 / 117 / 116 `emerging`), поэтому выигрыш нормировки внутри запроса против
абсолютной шкалы этими числами не показан и в одной постановке не перемерен (техдока §5 шаг 7,
`docs/todo.md` §118). `--drop-embed` — цена `E` во времени живого `ask`.

**E1. Правило не выполнено на одном из фолдов** (шаг 6). Модель не ставится; вывод «признаки
на срезе рост не предсказывают» или «модель = momentum» — результат для отчёта, не повод
крутить пороги. Выдача остаётся на прежней `growth.json`.

**E2. Контракт признаков разошёлся** (шаг 7). `weak.model.load` отказывается грузить модель,
не прошедшую гейт или с чужим набором признаков (`test_load_refuses_model_that_failed_the_gate`,
`test_shipped_growth_params_match_feature_contract`); выдача без модели — порядок по запасному
ключу BR-08.

**E3. Срезы на разных горизонтах** (шаг 2). Скрипт сверяет `backtest_signals.HORIZON_YEARS` и
`weak.core.SLICES` обучающих и проверочных срезов и при расхождении отказывается обучать —
пересчитать UC-25. В коде сверки нет: требование записано только в докстринге
`scripts/train_growth_model.py:39-40` (см. DoD «код расходится»). Разделы openalex у срезов
различаются по построению (у bt-2020 нет Computer Science и Engineering), и отказ или пометка
при таком расхождении — открытый вопрос `OQ-27`.

## 8. Особые требования

- BR-08, BR-09, BR-10 (вероятность, предикторы = разложение той же суммы), BR-28 (модель в
  `models` отчёта с ролью «скоринг»), BR-49, BR-50.
- NFR-39, NFR-44; `OQ-01` — определение уверенности принято по этой модели.
- Признаки — внутри запроса (query-level normalization): доля свежих работ плывёт между
  эпохами, место среди соседей по запросу — нет. Выигрыш нормировки против абсолютной шкалы
  на пулах с научным потоком в одной постановке не перемерен (A4, техдока §5 шаг 7).
- Вероятность и предикторы — одно линейное разложение (вклад = вес × z-значение), не
  постфактум-объяснение.
- Цена: скоринг в выдаче не стоит ни прохода по корпусу, ни вызова модели (доли секунды).
