# Vision: АС ПЕЛИКАН

Артефакт RUP «Vision»: зачем система, кому, что она делает на уровне возможностей и в
каких рамках. Детализация — в модели сценариев (05, use-cases/) и дополнительной
спецификации (06).

## 1. Введение

### 1.1 Назначение документа

Зафиксировать проблему, позиционирование, пользователей и перечень возможностей
АС ПЕЛИКАН так, чтобы заказчик, жюри и команда понимали продукт одинаково, а каждый
сценарий и нефункциональное требование вели к названной здесь возможности.

### 1.2 Область

Автоматизированная система поиска слабых сигналов технологических трендов. Вход —
направление в свободной форме по-русски; выход — ТОП-15 зарождающихся технологий с
описанием, преимуществом, кейсом, источниками (с атрибутами по ТЗ), уверенностью модели,
объяснением и гипотезой; отдельно — всё исключённое с причиной. Система включает
веб-интерфейс, API с очередью, конвейер инференса на локальных моделях, хранилище
корпуса и отчётов, сборщики корпуса, инструменты оценки качества и развёртывание стенда.

### 1.3 Контекст

ЛЦТ-2026, задача «Радар слабых сигналов технологических трендов», кейс Газпромбанк.Тех.
Команда «Zama» (Омск). Публичный стенд `https://pelican.chinchilla-ilish.ts.net`.
Репозиторий `trends-anal`, подпроект `pelican/`, базовая линия — `master@1dded3e`.

### 1.4 Ссылки

`../techdoc.md` (как сделано), `../../README.md` (как запустить), `../../reports/weak-eval.md`
(оценка качества), `../presentation.pdf` (презентация), `../final-measure.md` (замеры
доработок), `../../review/backend-review.md` (ревью бэкенда), прототип интерфейса
`../../prototypes/ui-v2/`.

## 2. Позиционирование

### 2.1 Проблема

| | |
|---|---|
| **Проблема** | Технологическую разведку банка интересуют технологии за 1–2 года до того, как они станут рынком. Когда о технологии пишут все, окно уже закрыто. Ручной мониторинг аналитиков и счётчики упоминаний не отделяют зрелое от нового: о зрелом тоже публикуют |
| **Затрагивает** | Технологическую разведку, R&D и инвестиционный комитет банка; методологов, которые сегодня ведут список слабых сигналов вручную |
| **Следствие** | Поздние решения, пропущенные направления, список сигналов, который невозможно воспроизвести и обосновать источниками |
| **Успешное решение** | По открытому запросу за ≤ 20 минут даёт воспроизводимый, объяснимый и проверяемый по источникам ТОП-15 зарождающихся технологий, отделяет зрелое, стандарты, хайп и шум с причиной словом ТЗ у каждого исключённого (`BR-03`; мерило — контроль 30 из 30 не принят за сигнал, `reports/weak-eval.md`), и работает внутри контура банка на локальных моделях |

### 2.2 Позиционирование продукта

| | |
|---|---|
| **Для** | аналитиков технологической разведки, R&D и инвестиционного комитета банка |
| **Которые** | должны находить зарождающиеся технологии раньше рынка и обосновывать каждую источниками |
| **АС ПЕЛИКАН** | автоматизированная система (радар) поиска слабых сигналов |
| **Которая** | по направлению в свободной форме находит ТОП-15 зарождающихся технологий по двум потокам — научному (15 млн работ) и денежному (новости о раундах и пилотах), оценивает зрелость по шести классам ТЗ, объясняет уверенность и показывает каждый источник с датой, типом, языком и доверенностью |
| **В отличие от** | мониторинга упоминаний и ручного ведения списков, а также облачных LLM-сервисов, которые выдают знания модели без подтверждённого поиска и выносят данные за контур |
| **Наш продукт** | строит выдачу только по найденному, считает отсев вслух, работает на локальных моделях и укладывается в 20 минут |

очереди.

## 4. Обзор продукта

### 4.1 Перспектива

Три слоя по ТЗ: интерфейс (React-приложение `web/`),
инференс (FastAPI с очередью и единственным исполнителем конвейера `weak.ask`, локальные
модели в LM Studio), хранение и сбор (Postgres 18 с корпусом, разметкой, очередью и
отчётами; шарды векторов; сборщики arXiv/OpenAlex). Диаграмма контекста —
`diagrams/context.puml`, архитектура — `../architecture.puml`.

### 4.2 Допущения и зависимости

- На хосте стенда запущен OpenAI-совместимый сервер моделей с `google/gemma-4-12b-qat` и
  `google/embedding-gemma-300m`; GPU ≈ 12 ГБ.
- Корпус и шарды наполнены заранее (≈15 млн работ, ≈22 ГБ шардов; точные числа — `OQ-13`); чистый `compose up`
  даёт пустой корпус.
- Открытые источники (Google News, КиберЛенинка, Хабр, GitHub, EPO OPS, arXiv, OpenAlex)
  доступны из контура; их отказ не фатален, но обедняет выдачу.
- Публичный доступ — через Tailscale Funnel; порты сервисов опубликованы только на
  127.0.0.1.
- ТЗ заказчика в репозитории нет; требования опираются на его цитаты в коде (02, приложение)
  и на консультацию с экспертами заказчика 16.10.2026.

### 4.3 Стоимость и лицензирование

Open-source стек (FastAPI, Postgres, React, Vite). Модели Gemma — локально. OpenAlex
считает запросы в деньгах (≈ $0.0001 за запрос, свободный ключ — $1 в сутки). EPO OPS
требует ключи. Облачная модель (`sonar`) использовалась только в замере и в стенде не
применяется.
