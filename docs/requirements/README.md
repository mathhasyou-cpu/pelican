# Требования к АС ПЕЛИКАН — набор артефактов RUP

Автоматизированная система поиска слабых сигналов технологических трендов (АС ПЕЛИКАН;
в коде и README — Pelican). ЛЦТ-2026, задача «Радар слабых сигналов технологических
трендов», кейс Газпромбанк.Тех.

Этот каталог — **Software Requirements Specification (SRS)** системы в смысле RUP: SRS не
отдельный файл, а пакет «модель сценариев использования + дополнительная спецификация»,
окружённый Vision, запросами заинтересованных сторон, глоссарием, бизнес-правилами и
трассировкой. Техническая документация «как сделано» — `../techdoc.md`; здесь — «что
требуется, кем и как проверяется».

## Порядок чтения

1. Новому участнику: Vision → Глоссарий → обзор сценариев (05) → один сценарий из пакета A
   (например, `UC-01`) → бизнес-правила.
2. Разработчику перед задачей: сценарий → его DoR → бизнес-правила и NFR по ссылкам из
   сценария → трассировка к тестам.
3. Приёмщику/жюри: Vision §5 (возможности со статусами) → `07-traceability.md` → DoD
   нужных сценариев.
4. Аналитику при изменении: `08-requirements-management-plan.md` (процедура) →
   `09-open-questions.md`.

## Схема идентификаторов

| Префикс | Тип | Где определён |
|---|---|---|
| `STR-NN` | запрос заинтересованной стороны | 02 |
| `FEAT-NN` | возможность продукта | 01 §5 |
| `UC-NN` | сценарий использования | 05, use-cases/ |
| `BR-NN` | бизнес-правило | 04 |
| `NFR-NN` | нефункциональное требование | 06 |
| `OQ-NN` | открытый вопрос | 09 |

Идентификаторы не переиспользуются: снятое требование остаётся в документе со статусом
«Снято» и причиной.

## Статусы требований

| Статус | Значение |
|---|---|
| **Реализовано** | есть в коде базовой линии `master@1dded3e`, проверяется названными тестами или процедурой |
| **Реализовано за флагом** | код есть, в коде по умолчанию выключен (`weak/flags.py`, переменные `WEAK_*`); включается в `.env` стенда по правилу замера или записанным решением владельца (`OQ-17`: на стенде включены `WEAK_LAYERS` и `WEAK_EXTRA_SOURCES`) |
| **Прототип** | согласовано и показано в кликабельном прототипе `prototypes/ui-v2/` (этап 6 плана реализации), в коде стенда отсутствует; ранние концепты — `prototypes/ui-concepts/` |
| **Предложено** | пробел, обнаруженный при анализе; решение за заказчиком/командой |
| **Снято** | требование отозвано; причина указана |

Базовая линия фактов: репозиторий `trends-anal`, ветка `master`, коммит `1dded3e`
(2026-10-20). Строки кода, имена тестов и статусы в документах относятся к этому состоянию.
Ветка `pelican-web` базовой линией набора не является.

## Как поддерживать

Набор живёт рядом с кодом и правится точечно вместе с ним: меняется поведение — меняется
сценарий, его DoD и строка трассировки. Правила — в
[08-requirements-management-plan.md](08-requirements-management-plan.md).
